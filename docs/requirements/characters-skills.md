# Functional requirements: character creation and development

**Current status:** the status of each requirement in this document, the implemented scope, the remainder and the documentation are in the [coverage matrix](coverage/characters-skills.md) (re-checked 2026-10-20, ARC-DEV-027). The "Steamwoven" fields below and the summary coverage section are details as of the date of their last edit (initial audit 2026-10-09, merged main [`a8a553b7`](https://github.com/Simarglok/arcanum-steamwoven/tree/a8a553b7c406ace77ea019bf2b13251f00ecddb6), PR #54); where they differ, the matrix is correct.

**Research cut:** 2026-10-02. The original's behavior is given by function addresses of the retail `Arcanum.exe` 1.0.7.4 in parentheses. Initial Steamwoven research commit: `b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae`. This document covers only the character and development, not a full Arcanum audit and not an approved backlog.

## How to read the conclusions

- **Original functions** — reading of the original's functions at the given addresses, level F0 (not verified in the exe), unless the line is in the verification ledger. The lines of the [verification ledger](../research/original-verification-ledger.md) (XP, AL, CS, SK, EF, BC) are behavior verified in 1.0.7.4. Without a ledger line this is not a check of the executable, its data or the game behavior.
- **Steamwoven proposal** and the acceptance scenarios describe a project goal for discussion; they are not an already accepted product contract.
- **Unknown** means that the related game data, another domain or the original runtime has not been studied enough to draw a conclusion.
- Artifact/game sources were not read or copied. Steamwoven decisions set an independent C#/Godot implementation and do not confirm a finished character simulation. [Architecture direction](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/architecture/decisions.md#L7-L18), [implementation catalogue and absence of a game world](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L27).

The labels **provisionally for pre-alpha** and **later** below are scope candidates for this domain only; they do not define the full pre-alpha content, deadlines, the task queue or the authority to assign tasks. Provisional candidates for pre-alpha: FR-CHAR-001–011, FR-CHAR-013–020 and FR-CHAR-026. FR-CHAR-012 and FR-CHAR-021–025 may be considered later, after the needed data and runtime contracts are verified. The owner assigns tasks, and the product contract requires later verification by the owner-player.

## Requirements

<a id="fr-char-001"></a>

### FR-CHAR-001 — Creating a PC with initial attributes

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** character creation forms a separate PC object with initial values, level one and development points; the requirement covers a new creation scenario, not pre-made heroes. **Original functions:** the main menu creates a PC from the chosen prototype; player creation (0x40DB70) makes it the current character and sets level 1 (0x4A6F00), and the initial values (0x4B0450) set the starting attributes to 8 and 5 unassigned points. Main-menu creation (0x5446F0), PC creation and initial level (0x40DB50, 0x40DB70), initial attributes (0x4B0450). **Dependencies:** the PC prototype, the attribute schema and a profile of initial rules. **Acceptance check:** on a synthetic profile create two characters, check the same initial values under the chosen rules and different IDs. **Steamwoven:** partial, in the viewer: the main-menu new-character window ([ARC-UI-030](../rendering/terrain-viewer.md#new-character-window-arc-ui-030), checked against the exe [NW1–NW6](../research/ledger/character.md#new-character-window-arc-ui-030)) makes a PC from prototype 16066 with level 1, attributes 8 and 5 points; its Accept opens the character editor in creation mode ([ARC-UI-034](../rendering/terrain-viewer.md#character-editor-in-creation-mode-arc-ui-034), checked against the exe [CM1–CM8](../research/ledger/character.md#character-editor-in-creation-mode-arc-ui-034)), where the 5 points are spent and returned before the character starts, and the editor's Accept starts the game with the name, portrait (ARC-UI-033) and the purchased attributes and skills; there is no shop yet.

<a id="fr-char-002"></a>

### FR-CHAR-002 — Name and completing character creation

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** the name is set at creation; an empty value, or one left as the hint value, does not allow the process to finish, and the entered value is stored in the player's name field. By F0 the input field has size 23 and checks for the hint value, but this does not confirm the rules for spaces, uniqueness and normalization. **Call path:** main-menu name field → creation completion (0x545780) → `OBJ_F_PC_PLAYER_NAME`. Field size and focus (0x5493C0), name check and write (0x545780). **Dependencies:** a safe string name field and a length/character policy. **Acceptance check:** an empty or hint value does not complete creation; a valid name is saved in the PC and shown when the profile is reopened. **Steamwoven:** partial, in the viewer: the name field of the new-character window ([ARC-UI-033](../rendering/terrain-viewer.md#new-character-window-arc-ui-030), checked against the exe [NW6–NW9](../research/ledger/character.md#new-character-name-and-portrait-arc-ui-033)): the field starts with message 500, a click clears it, input of bytes from 0x20, appended at the end, up to 22 bytes, Backspace, Enter (an empty field gets message 500), a click outside the field (an empty field gets its previous text); Accept refuses with message 506 on a name equal to message 500, otherwise the name is stored in the hero session (`SetHeroPlayerName`, schema 56) and shown in the status lines; the cursor keys, Delete and Insert are not offered.

<a id="fr-char-003"></a>

### FR-CHAR-003 — Permitted race and gender combinations

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** the editor offers eight race entries (IDs 0–7), stores gender separately and excludes forbidden combinations; changing the race changes the body type and resets the previous background. The table allows both genders for Human, Elf, Half-Elf and Half-Orc; for the others the female gender is marked invalid. **Call path:** race/gender buttons → choice by the table → setting the object's gender and race (0x441C70) and a new portrait pick. Race and body-type table, gender change (0x545350, 0x5453A0), race change (0x545490, 0x545550, 0x5455D0). **Dependencies:** versioned race/gender definitions and the body-type mapping. **Acceptance check:** go through all eight races and the permitted gender values; a forbidden combination is unavailable, the permitted variants cycle. **Steamwoven:** partial, in the viewer: `CharacterCreationRules` and the new-character window ([ARC-UI-030](../rendering/terrain-viewer.md#new-character-window-arc-ui-030), checked against the exe [NW2–NW5](../research/ledger/character.md#new-character-window-arc-ui-030)): permitted pairs, race and gender buttons, background reset, race and gender effects; body type and graphics by race and gender — N15.

<a id="fr-char-004"></a>

### FR-CHAR-004 — Picking a portrait by race and gender

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** portrait selection iterates the entries that fit the current race and gender, allows a common `ANY` and separates game and user IDs; when the race or gender changes, the first suitable portrait is chosen. The code confirms the filter by message-file prefix and getting an image by ID, but not the content of the catalogue itself. **Call path:** race/gender change → first suitable portrait (0x4CE6B0); browse buttons → previous/next portrait (0x4CE9B0, 0x4CE8B0) → writing the ID into the critter. Portrait sources (0x4CE350, 0x4CE390, 0x4CE3C0), iteration with a filter (0x4CE6B0, 0x4CE7A0, 0x4CE8B0, 0x4CE9B0), admission and reading the ID (0x4CEAC0, 0x4CEB80), portrait-choice calls (0x544FF0). **Dependencies:** the portrait catalogue, stable IDs and display. **Acceptance check:** in a synthetic catalogue return only compatible and universal entries; the chosen ID is kept when the profile is refreshed. **Steamwoven:** partial, in the viewer: the `PortraitCatalogue` reader ([ARC-DATA-045](../research/ledger/character.md#portrait-catalogue-arc-data-045), checked against the exe PO1–PO10) gives image paths, admission, search and creation buttons; the new-character window ([ARC-UI-033](../rendering/terrain-viewer.md#new-character-window-arc-ui-030), [NW9](../research/ledger/character.md#new-character-name-and-portrait-arc-ui-033)) browses portraits with the buttons and takes the first suitable one when the race or gender changes; the hero's portrait (field 0xE7) is stored in the session (schema 56), for a ready hero from the prototype; the portrait image is not drawn in the window yet (file name and ID).

<a id="fr-char-005"></a>

### FR-CHAR-005 — Choosing a permitted background

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** the list of backgrounds is filtered by the race/gender prefix and the special `ANY`/`NPC` conditions; the choice stores the background ID and the linked description ID and applies the effect, and a reset removes the effect by its cause. This does not confirm specific texts or game effects. **Call path:** forward/back buttons → background search (0x4C2300, 0x4C2390, 0x4C2420) → assign/reset (0x4C25E0, 0x4C2650); the hero card reads the description by ID. The background effect is added only on a button press ([Character creation](../research/ledger/character.md#skills-levels-and-character-arc-res-044-arc-res-031-arc-res-027)). Choice and admission (0x4C2300, 0x4C2390, 0x4C2420), assignment and effect (0x4C25E0, 0x4C2650, 0x4C2690, 0x4C26D0), race/gender conditions (0x4C2B50), the menu's choice call (0x544FF0, 0x5452C0, 0x545300). **Dependencies:** versioned backgrounds, an effect catalogue and localized descriptions. **Acceptance check:** show only backgrounds compatible with the race and gender; a repeated choice updates one record and the linked effect without accumulating. **Steamwoven:** partial, in the viewer: the `BackgroundTable` reader ([ARC-DATA-044](../research/ledger/character.md#background-table-arc-data-044), checked against the exe BD1–BD8) gives blocks, admission, search and creation buttons, description and effect numbers and the description text; setting and clearing the hero's background in the session with the effect of cause 1 ([ARC-WORLD-097](../world/equipment-runtime.md#setting-and-clearing-the-background-arc-world-097), checked against the exe BD9–BD11); there is no creation screen. The new-character window ([ARC-UI-030](../rendering/terrain-viewer.md#new-character-window-arc-ui-030)) browses and sets a background with its effect and shows its text.

<a id="fr-char-006"></a>

### FR-CHAR-006 — Contextual background effects

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** the background's contextual modifiers depend on time, tile type, lighting or surface, so an effective attribute can change after a move to another place or a change of time without changing the base. The original's functions (F0) contain indoor/outdoor and surface-type checks; the full set of effects from the data has not been studied. **Call path:** effective attribute (0x4B0490) → context/tile/time check → effect modifier → clamp to the range. Context branches and effect pipeline (0x4B0490), tile flag queries (0x4EBAD0, 0x4EBB30, 0x4EBB80, 0x4EBBA0). **Dependencies:** the character's location, tile classification, time and the effects runtime. **Acceptance check:** on a synthetic set a controlled change of context changes the effective value without overwriting the base. **Steamwoven:** partial ([ARC-WORLD-069](../world/equipment-runtime.md#backgrounds-arc-world-069), checked against the exe BG1–BG8): the hero's background id is stored in the session (schema 36; ready heroes 39–50 from the prototype, an NPC has no background — the original's reader 0x4C2690 answers 0 for a non-PC); Magick Allergy (69) does not let the hero wear a magickal item (wear check 0x464D20, code 18), Technophobia (72) does not let the hero take a technological item (insert check 0x466510, code 15) — on pickup, looting, `IN`, a build product and removing a worn item (0x464C80). **Remains (out of scope):** choosing the background at character creation (0x5448E0, 0x4C25E0, 0x4C2650, 0x4C2B50); the background effect line (`rules\effect.mes`, cause 1); starting gold and items (0x4C26F0, FR-CHAR-007); speech "like an idiot" (55, 74, 75; 0x45FC00); dark sight (78; 0x45FB90, 0x4C8430); contextual attribute changes 62–68 (0x4B0490: time, street, nature, water, light); Educator (51; 0x4C2950, FR-CHAR-018); the container generation seed (0x463E20); the multiplayer gold multiplier (0x4A5710).

### FR-CHAR-007 — Starting kit by background

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** at initial setup the character receives the gold and item prototypes specified by the chosen background, before the usual racial auto-equipping. The requirement does not define exact items, sums or a general equipment policy. **Call path:** inventory generation (0x460FF0) → background set (0x4C26F0) → the given gold and items. Background data application (0x4C26F0), inventory caller (0x460FF0). **Dependencies:** item prototypes, inventory, economy and background data. **Acceptance check:** two synthetic backgrounds give their own starting kits exactly once; a reset and a repeated choice during creation does not duplicate items. **Steamwoven:** partial: a ready hero gets the `InvenSource` set (ARC-WORLD-015, ARC-WORLD-034); a new character gets the opening-shop set (window 15, [ARC-UI-036](../rendering/terrain-viewer.md#opening-shop-arc-ui-036), checked against the exe [OS1–OS6](../research/ledger/character.md#opening-shop-arc-ui-036)): money and items of the background, clothes or a jacket, lockpicks and bandages; barter with the shop map's merchant on a session created on ShopMap, which the game continues ([ARC-UI-038](../rendering/terrain-viewer.md#opening-shop-merchant-arc-ui-038), checked against the exe [OS7–OS10](../research/ledger/character.md#opening-shop-merchant-arc-ui-038)).

<a id="fr-char-008"></a>

### FR-CHAR-008 — Base and effective attribute values

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** the stored base value is separate from the current effective value; the effects layer applies modifiers and clamps the result. A change of the base triggers dependent updates, so the interface and game systems read a single authoritative character state. The lifetime of individual effects is described in FR-CHAR-022. **Call path:** the character sheet shows base and effective values; the setter changes state, the getter accounts for effects. Getter and clamp (0x4B0490), base get/set and stat side effects (0x4B0740, 0x4B0980), character sheet rendering (0x55B280, 0x55B2A0). **Dependencies:** attribute definitions, the order of modifiers and their consumers. **Acceptance check:** adding and removing a synthetic effect changes the effective value without touching the stored base and returns the result to the initial one. **Steamwoven:** partial — ARC-WORLD-012 added a Godot-free attribute owner: the base separate from the effective value, adding/removing an effect per instance, synthetic tests; not connected to the session, dialog and interface, [runtime](../world/character-stats-runtime.md). [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-009"></a>

### FR-CHAR-009 — Racial and gender modifiers

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** changing the race or gender removes the previous modifiers and assigns new ones; the original's code rule for the female gender changes Strength to −1 and Constitution to +1, and the racial effect is chosen by the race ID. The effect tables of specific races and their values depend on the data. **Call path:** race/gender setter → setting the base (0x4B0980) → remove the previous cause → write the base → apply the new effect. Setter side effects (0x4B0980), effect causes/adjustment (0x4E9F70), race/gender caller (0x5453A0). **Dependencies:** effect descriptions and stable causes of their application. **Acceptance check:** on repeated switching of race/gender the previous innate effect is removed before the new one is assigned and does not accumulate. **Steamwoven:** partial — ARC-WORLD-012: changing the race/gender removes the previous innate effect before the new one is assigned; the content of the effects is set by the caller, `effect.mes` is not read, [runtime](../world/character-stats-runtime.md). [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-010"></a>

### FR-CHAR-010 — Racial attribute limits

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** the setter limits an attribute to the permitted minimum and maximum; the upper limit of the main attributes depends on the race, and the effective value is also clamped after the modifiers are applied. The numbers are set in the original's code (0x4B0FC0, 0x4B0FD0, F0), but the project's game values should be checked against the chosen compatible version and rule set. **Call path:** a purchase checks the limit → setting the base (0x4B0980) clamps the value → the effective attribute (0x4B0490) returns the result; skill limits also use tables of key attributes. Min/max and racial maxima (0x4B0FC0, 0x4B0FD0), editor purchase checks (0x55A5C0). **Dependencies:** the race profile, attribute limits and the accepted effects policy. **Acceptance check:** for each race check a value below, at and above the limit; a rejected purchase changes neither the attribute nor the budget. **Steamwoven:** partial — ARC-WORLD-012: racial maxima by the attribute limit (0x4B0FD0, level F0), a value out of range is rejected without change; there are no purchases or budget, [runtime](../world/character-stats-runtime.md). [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

### FR-CHAR-011 — Derived attributes

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** derived values are computed read-only from the effective main attributes and the world context. Examples in the original (0x4B0740): carrying capacity, damage bonus, defense, speed, healing rate, poison recovery, reaction, follower limit and magick-technology aptitude. They cannot be written directly through setting the base (0x4B0980); the character sheet shows the effective values of attributes 8..15 ([CS6](../research/ledger/character.md#character-sheet-arc-ui-007)); combat formulas and the outcome of combat are described by a separate domain. **Call path:** interface or game system → base value (0x4B0740) → formula of the derived quantity → current context. Derived stat branches (0x4B0740), derived setters rejected (0x4B0980). **Dependencies:** attribute definitions, time/sector and the dependent combat and economy domains. **Acceptance check:** a change of Strength/Charisma/Constitution affects the corresponding derived quantities; a write to a derived field does not change the result. **Steamwoven:** partial — ARC-WORLD-012: nine read-only derived quantities from effective values and an explicit sector context; a write is rejected, [runtime](../world/character-stats-runtime.md). [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

### FR-CHAR-012 — Character sheet and resistances

**Stage:** later. **Behavior and boundaries:** the character sheet distinguishes main, base and effective values, shows secondary attributes and five resistances through the object API. The resistance formula and its effect on damage belong to the effects and combat domains. **Call path:** sheet refresh → attribute getter and reading the object's resistance in the "for display" form (0x43D6D0) for the resistance rows ([CS6](../research/ledger/character.md#character-sheet-arc-ui-007), [EQ8](../research/ledger/items.md#equipment-arc-world-028)). Sheet stat/resistance rows (0x55B1B0, 0x55B280, 0x55B2A0), resistance key categories. **Dependencies:** a single character state, resistance effects and a readable interface. **Acceptance check:** a controlled change of a resistance is reflected in the right row without changing the other rows. **Steamwoven:** ARC-UI-007 added to the AREA viewer a diagnostic view-only sheet of the session hero (key `C`, checked against the original exe): effective main attributes marked "raised/lowered by effects" (not innate ones), eight derived values, HP and fatigue, level, experience to the next level, alignment and aptitude ([viewer](../rendering/terrain-viewer.md#character-sheet-arc-ui-007)). Resistances are partial: only worn armor and the Constitution bonus to poison; there is no base field and no resistance effects in the session. There is no purchase of points, skills or a game screen. Historical cut: [project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L13-L14), [not implemented](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

### FR-CHAR-013 — Experience accumulation and level thresholds

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** a PC's experience accumulates in one attribute; the level thresholds are taken from a versioned rules table, drive the progress indicator and are capped by a set maximum. Combat, quests, dialogs and scripts use shared experience-award paths, but the rules of their rewards are not covered here. **Call path:** reward source → experience award (0x45F110) → `STAT_EXPERIENCE_POINTS` → level recalculation (0x4A69C0); the character sheet shows the remainder to the level. XP award (0x45F110), threshold loading (0x4A6620), progress and level recalc (0x4A68B0, 0x4A6900, 0x4A6980, 0x4A69C0), XP stat hook (0x4B0980). **Dependencies:** the rules table, a difficulty policy and trusted reward sources. **Acceptance check:** synthetic thresholds are checked below, at and above the threshold, for several levels and the cap level. The terminal branch differs from an ordinary level-up ([XP5](../research/ledger/character.md#experience-and-levels-arc-world-030), [LM11](../research/ledger/character.md#skills-levels-and-character-arc-res-044-arc-res-031-arc-res-027); see FR-CHAR-014). **Steamwoven:** partial, [ARC-WORLD-030](../world/experience-runtime.md): the hero's experience in the session, the award by the experience-award rules (0x45F110) (difficulty, `xpgain` effects, nothing for the dead), thresholds from `xp_level.mes`, the remainder to the level and progress; checked against the exe (XP1–XP12: on "hard" difficulty the original takes away a quarter of the gain, [XP1](../research/ledger/character.md#experience-and-levels-arc-world-030)). The host (viewer, character sheet) is not connected.

<a id="fr-char-014"></a>

### FR-CHAR-014 — Development points for a level-up

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** when one or more experience thresholds are crossed, the level rises and free development points are added. The point calculation (0x4A6980) gives one point per level and one more on every fifth level ([XP4](../research/ledger/character.md#experience-and-levels-arc-world-030)); the level recalculation (0x4A69C0) applies it and refreshes the UI in the ordinary branch. The cap is level 50: reaching level 51 only returns the experience to the level-50 threshold, without setting the level or granting points ([LM11](../research/ledger/character.md#skills-levels-and-character-arc-res-044-arc-res-031-arc-res-027), [XP5](../research/ledger/character.md#experience-and-levels-arc-world-030)). These points are spent on attributes and skills; the rules of combat experience rewards are not included here. **Call path:** setting `STAT_EXPERIENCE_POINTS` (0x4B0980) → level recalculation (0x4A69C0) → points update → level notification. Point schedule and level-up loop (0x4A6980, 0x4A69C0), level UI caller effect (0x4B0980). **Dependencies:** level thresholds, the development-points register and the purchase API. **Acceptance check:** crossing a level grants the configured budget once, including for several levels in one award; repeated processing does not duplicate points. **Steamwoven:** partial, [ARC-WORLD-030](../world/experience-runtime.md): the level recalculation in the session records each level reached with its points (1 per level, 2 for every fifth, no more than 56 free); the terminal branch is verified in the exe (XP5): the original leaves the hero at level 50 and returns the experience to the level-50 threshold ([LM11](../research/ledger/character.md#skills-levels-and-character-arc-res-044-arc-res-031-arc-res-027)). Auto-level schemes spend the hero's points at every level, and companions level up after the hero ([ARC-WORLD-036](../world/advancement-runtime.md)); the player's purchase of points is not implemented. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-015"></a>

### FR-CHAR-015 — Buying and returning attribute points

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** free points are spent to raise a main attribute at a set cost; lowering it with a return of points is possible only down to the editor's confirmed value. A decrease is rejected if it violates the current requirements of skills, spells or technologies. **Call path:** editor button → cost and budget check → setter and requirement check → budget and interface update. Increase/decrease event handling (0x55A5C0), accepted-value snapshot (0x5597C0), stat cost/clamping (0x4B0980), prerequisite guards (0x4B0980). **Dependencies:** the common budget, attribute limits and the check of skill/magick/technology requirements. **Acceptance check:** a permitted raise spends the needed number of points; a lack of budget or a violation of requirements on a decrease changes neither the attribute nor the budget. **Steamwoven:** partial, [ARC-WORLD-052](../world/character-point-pool.md): the common path for spending and returning points in the session — raising an attribute at the cost `StatCost(base + 1)`, refusal when the effective value is at the race's maximum, a return only while the editor is open and only down to the value at the moment it was opened (strictly in both modes), a refusal of a decrease by the requirements of skills, spells and degrees (checked against the exe, [CP1–CP12](../research/ledger/character.md#character-point-pool-arc-world-052)); spell ranks are bought and returned through the same path ([ARC-MAGIC-004](../world/spell-book-runtime.md), SB8, SB10); the "+" and "−" buttons of attributes and pools on the attributes page of the sheet and of the creation-mode editor ([ARC-UI-034](../rendering/terrain-viewer.md#character-editor-in-creation-mode-arc-ui-034), CP3, CP4, CM8). [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-016"></a>

### FR-CHAR-016 — Distributing ranks of main skills

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** buying each skill rank spends the specified number of character points; the base value grows by four per allocated skill point, the effective value accounts for modifiers and is capped by the key attribute. Returning a rank returns the budget only down to the confirmed value. **Call path:** +/- button in the sheet → increase/decrease of the skill in the interface (0x57ACD0, 0x57AEB0; one "−" click removes points until the level changes and returns each of them, [SK2](../research/ledger/character.md#skills-levels-and-character-arc-res-044-arc-res-031-arc-res-027)) → setting the skill points (0x4C6000) → change of free points and interface refresh. Rank model and key-stat cap (0x4C5E50, 0x4C5EB0, 0x4C5F70, 0x4C5FA0, 0x4C6000), rank cost/key stat (0x4C64B0, 0x4C64C0, 0x4C64D0, 0x4C64E0), UI purchase/refund (0x57ACD0, 0x57AEB0), character editor caller (0x55D3A0). **Dependencies:** the link of skills to the key attribute and the point budget. **Acceptance check:** each permitted rank changes the distribution and the remaining points; an invalid or too expensive rank changes neither. **Steamwoven:** partial, [ARC-WORLD-052](../world/character-point-pool.md): buying and returning main-skill points through the common session path; the "−" click by default is as in the original (until the level changes), but it stops at the editor's opening value in both modes (CP6, a bug of the original, a fix is recommended), the "one point" variant is an option for S6 (checked against the exe, [CP1–CP12](../research/ledger/character.md#character-point-pool-arc-world-052)); there are no buttons in the sheet (S6). [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-017"></a>

### FR-CHAR-017 — Technological skill ranks and technology aptitude

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** technological skill ranks spend the common budget and are subject to the key attribute; a successful change also updates the sum of tech points used in computing the magick-technology aptitude. The requirement ends at development and does not set the result of hacking, traps or weapon actions. **Call path:** editor → setting technological skill points (0x4C66E0) → storing ranks and `STAT_TECH_POINTS` → updating related items/effects and the derived aptitude. Tech rank validation and aptitude update (0x4C6580, 0x4C65E0, 0x4C6680, 0x4C66E0), tech skill key mapping, UI point-budget consumer (0x57ACD0). **Dependencies:** technological skill definitions, limits by key attributes and the aptitude model. **Acceptance check:** a permitted technological rank spends the set points, increases tech points by the accepted amount and updates the derived views. **Steamwoven:** partial, [ARC-WORLD-052](../world/character-point-pool.md): buying and returning technological skill points with a change of tech points through the common session path, one point at a time (checked against the exe, [CP1–CP12](../research/ledger/character.md#character-point-pool-arc-world-052)); degrees of disciplines are bought and returned through the technology strip ([ARC-TECHNOLOGY-002](../world/tech-degrees-runtime.md): effective Intelligence, +1 tech point, a return only down to the value at editor opening — TC10), effective expertise with discipline effects; there are no buttons in the sheet (S6). [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-018"></a>

### FR-CHAR-018 — Training levels and the Educator background

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** main and technological skills have consecutive training levels; the next one can be reached after the configured skill minimum is reached. The Educator background can pass a higher training level of the PC to followers. Setting training from the interface (0x57AC90) in the original routes main and technological skills correctly, except skill 12 (Repair): it goes to the main-skills setter and is rejected; only the multiplayer handler calls this function ([SK3](../research/ledger/character.md#skills-levels-and-character-arc-res-044-arc-res-031-arc-res-027)). Tier rules and basic setter (0x4C60C0, 0x4C6170), technical setter (0x4C67F0, 0x4C6850), educator propagation (0x4C2950), suspect UI dispatch and callback wiring (0x57AC90), caller registration (0x57C6E0). **Dependencies:** training thresholds, skill type IDs and the follower model. **Acceptance check:** each skill family changes only its own training level; a tier cannot be skipped or chosen below the threshold; the Educator synchronization accounts for the follower's level. **Steamwoven:** absent. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-019"></a>

### FR-CHAR-019 — Skill application check

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** when a skill is applied to a permitted target, the check uses the current effective value of the skill and of training, accounts for the difficulty of the context and a random result, then passes the success or critical outcome to the skill handler. The consequences of combat and item actions are described by another domain. **Call path:** skill activation in the interface (0x57A320) → skill application → running the check (0x4C7160); suitable checks also call the fate handlers. The skill effectiveness formulas are checked in the exe; Dodge gives 2 × level ([Dodge (SKX1)](../research/ledger/character.md#skills-levels-and-character-arc-res-044-arc-res-031-arc-res-027)). UI dispatch (0x57A320), skill chance from current rank (0x4C62E0), invocation and fate outcome (0x4C7160). **Dependencies:** the action queue, target/context, a random generator and skill handlers. **Acceptance check:** with a fixed random value and context a change of the rank alone changes the probability; identical inputs give an identical outcome. **Steamwoven:** there is no simulation of skills and actions. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-020"></a>

### FR-CHAR-020 — The character's magick-technology aptitude

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** the character shows a derived balance of invested magick points, tech points and sector adjustments; the character sheet refreshes the corresponding scale. By F0, setting technological skill points (0x4C66E0) directly changes the sum of tech points; the aptitude scale on the sheet shows a non-negative value on the magick side and a negative one on the technology side ([CS7](../research/ledger/character.md#character-sheet-arc-ui-007)). The sources of magick points and the sector adjustment tables have not been studied. Derived aptitude getter (0x4B0740), tech-rank side effect (0x4C66E0), sheet refresh caller (0x55B150), aptitude display (0x55EC90). **Dependencies:** magick development, the sum of technological ranks, the sector profile and dependent systems. **Acceptance check:** an independent change of each synthetic input changes the aptitude in the set direction and triggers an update of the dependent values. **Steamwoven:** partial: aptitude is derived from magick and tech points ([attribute rules](../world/character-stats-runtime.md)); discipline degrees bought in the editor change tech points and thereby the aptitude ([ARC-TECHNOLOGY-002](../world/tech-degrees-runtime.md)); the technological skill and spell buttons in the sheet and in the creation-mode editor ([ARC-UI-034](../rendering/terrain-viewer.md#character-editor-in-creation-mode-arc-ui-034)) change tech and magick points and the aptitude on the sheet; there are no degree buttons in the viewer. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-021"></a>

### FR-CHAR-021 — Automatic allocation on a level-up

**Stage:** later. **Behavior and boundaries:** an optional scheme can automatically spend free points on attributes and development at a level-up or initialization; execution stops when there is no rule, not enough points or an unmet condition, and reports the applied changes to the PC interface. The parser also accepts categories of spells, technologies and others, but their mechanics are outside this domain. **Call path:** level recalculation (0x4A69C0) or level setting (0x4A6F00) → scheme lookup (0x4A6E40, [AL2](../research/ledger/character.md#auto-level-schemes-arc-world-036)) → rule handler → typed purchase functions. Scheme selection and rule lookup (0x4A6D40, 0x4A6D90, 0x4A6DE0, 0x4A6E40), level-up / initial level callers (0x4A69C0), rule processor (0x4A7030, 0x4A7340), stat/skill purchase helpers (0x4A75E0, 0x4A76B0, 0x4A77A0). **Dependencies:** scheme parsing, the attribute and skill API, versions of user and system rules. **Acceptance check:** a valid synthetic scheme spends points in order; an erroneous or unavailable purchase ends in a bounded error with no negative remainder and no retry. **Steamwoven:** partial, [ARC-WORLD-036](../world/advancement-runtime.md): the `gamelevel.mes`/`userlevel.mes` rules are read as the original reads them, the purchases of attributes, skills, spells, technologies and hit and fatigue points are checked against the exe (AL1–AL14); the hero's scheme works at creation and at every level, a companion's scheme and rule 70 after its level rises; in the viewer with `--hero`. There is no choice of a scheme by the player and no message to the interface. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-022"></a>

### FR-CHAR-022 — Permanent and temporary modifiers

**Stage:** later. **Behavior and boundaries:** character effects are stored separately from the base attributes and tied to a cause; the getter combines the modifiers in a defined order, and adding and removing updates the derived HP, fatigue and overload. The project's policy must distinguish permanent causes, temporary effects and removal of a specific source. This review confirms the modifier layer and the add/remove operations, but not the durations of all effect types. Cause-aware effect records (0x4E9F70), stat adjustment and ordering (0x4EA690, 0x4EA6C0), cause-based removal (0x4EA2E0, 0x4EA3C0). **Dependencies:** the effect catalogue, a time/event service and the origin of each effect. **Acceptance check:** add two synthetic causes and check the summation order; remove or end one — the independent cause remains. **Steamwoven:** absent. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-023"></a>

### FR-CHAR-023 — Blessing and curse records

**Stage:** later. **Behavior and boundaries:** a PC can store unique IDs of blessings and curses with the time of receipt; adding looks up the given effect, applies it and notifies the player/journal, and removal erases the record and the linked effect. Names, texts, IDs, durations and effect definitions are set by external rules. The code stores the time, but by itself this does not prove the expiry rules. **Call path:** system/script → add or remove → the effects runtime; the journal reads the records and the time. Blessing operations (0x4C4200, 0x4C4280, 0x4C42F0, 0x4C4420, 0x4C4450), curse operations (0x4C3D50, 0x4C3DD0, 0x4C3E40, 0x4C3F70, 0x4C3FA0). **Dependencies:** the effect catalogue, stable status IDs, time and the journal. **Acceptance check:** a repeated add does not duplicate a status; removal removes only its record and effect, keeping the others and the time of receipt. **Steamwoven:** there are no statuses and no game journal. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-024"></a>

### FR-CHAR-024 — Fate Points and deferred blessings

**Stage:** later. **Behavior and boundaries:** spending an available Fate Point either applies an instant effect at once or reserves a deferred choice; it can be canceled with a return of the point before a suitable event fires, after which the interface is refreshed. The full list of events and sources of points has not been studied. **Call path:** fate window → activation/removal → event-based fate resolution (0x4F5270; one calling path is skill application) → interface refresh. Fate flags and state transitions (0x4F5090, 0x4F50C0, 0x4F51B0, 0x4F5270, 0x4F52D0), UI gating and actions (0x56FBF0), activation/deactivation UI (0x56FE70, 0x56FF40), one event caller (0x4C7160). **Dependencies:** award of Fate Points, event handlers, states and the interface. **Acceptance check:** without points activation is impossible; a deferred choice spends the point once, a cancel returns it once, the event fires once; an instant effect is applied at once. **Steamwoven:** absent. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-025"></a>

### FR-CHAR-025 — Carrying capacity and overload

**Stage:** later. **Behavior and boundaries:** the current weight of items is compared with a carrying capacity computed from Strength; at a transition between overload bands the effects and the animation speed change, and on the heavy bands fatigue damage is planned. Item weight and inventory movement belong to the items domain; the exact penalties from the data are not given here. **Call path:** a change of Strength or inventory → overload recalculation (0x45F820) → overload, speed and fatigue effects. Capacity formula (0x4B0740), weight band and transition (0x45F790, 0x45F820), Strength setter caller (0x4B0980). **Dependencies:** the total weight of items, Strength, effects, time events and animation/actions. **Acceptance check:** a controlled change of weight switches the overload band; a change of Strength recalculates it at once; leaving a band removes the penalties. **Steamwoven:** there is no inventory and no game computation of overload. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).

<a id="fr-char-026"></a>

### FR-CHAR-026 — Life state and action restrictions

**Stage:** provisionally for pre-alpha. **Behavior and boundaries:** the death state is derived from the current HP; certain character actions are unavailable to a dead local PC, and it is not awarded experience. The transition to death, combat causes and the rules of return to life belong to the combat/states domain. **Call path:** HP → death check (0x45D8D0); the fate window, the character editor and the experience award check this flag (a dead local PC does not open the sheet, [CS2](../research/ledger/character.md#character-sheet-arc-ui-007); a dead PC gets no experience, [XP1](../research/ledger/character.md#experience-and-levels-arc-world-030)). Death predicate (0x45D8D0), editor gate (0x5597C0), fate UI gate (0x56FBF0), XP award guard (0x45F110). **Dependencies:** the HP state, combat and the policy of return to life. **Acceptance check:** the listed editing and fate actions are unavailable to a dead PC, and it is not awarded experience; if another subsystem explicitly allows an active state with positive HP, these permitted actions are available again. The check does not define the resurrection rules. **Steamwoven:** partial, [ARC-COMBAT-002](../world/life-state-runtime.md): the HP of the hero and NPCs in the session and death by the current HP; a dead hero gets no experience ([ARC-WORLD-030](../world/experience-runtime.md)); there is no editor and no fate yet, so there are no restrictions on them for a dead PC either. [Project status](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/project/status.md#L23-L26).
