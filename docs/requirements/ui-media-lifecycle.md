# UI, медиа и lifecycle — функциональные требования

**Текущий статус:** статус каждого требования этого документа, реализованный объём, остаток и документация — в [матрице покрытия](coverage/ui-media-lifecycle.md) (пересверено 2026-10-20, ARC-DEV-027). Поля «Steamwoven» ниже и сводный раздел покрытия — подробности на дату их последней правки (исходный аудит 2026-10-09, merged main [`a8a553b7`](https://github.com/Simarglok/arcanum-steamwoven/tree/a8a553b7c406ace77ea019bf2b13251f00ecddb6), PR #54); при расхождении верна матрица.

**Срез исследования:** 2026-10-02. **Объём:** главные и игровые экраны, доступ игрока к системам через UI, фильмы/слайды/звук, запуск игровой сессии, настройки и save/load. Это доменный раздел общего каталога, а не аудит всех функций игры, ресурсов или всех ветвей каждой группы функций.

**База.** Исследованы функции оригинального исполняемого файла 1.0.7.4 по указанным адресам и текущий Steamwoven `main` на [`b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae`](https://github.com/Simarglok/arcanum-steamwoven/tree/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae), срез PR #36. Каталог статуса Steamwoven отстаёт до PR #30; здесь состояние сверялось с кодом закреплённого HEAD. «Наблюдение по оригиналу» — чтение функций оригинала по указанным адресам, уровень F0 (не проверено в exe), если строки нет в [журнале сверки](../research/original-verification-ledger.md); оно описывает только прочитанные функции и caller chain. «Предложение проекта» и фазы Pre-alpha/Later предложены для проверки опытным игроком, не являются уже принятым контрактом. «Неизвестно» отмечает незакрытые ветви функций, данные, платформенные ограничения и поведение оригинального runtime.

Правила выбора/загрузки модулей и ресурсов принадлежат [данным, совместимости и современным целям](content-product.md). Часы/пауза — [времени и освещению](lighting-time.md); формулы персонажа — [персонажу и навыкам](characters-skills.md); эффектам предметов и торговли — [предметам и экономике](items-economy.md); боевым переходам — [бою, магии и технологиям](combat-magic-tech.md); диалоговой истории и сценарию — соответствующим story/social/AI документам. Этот раздел требует доступной игроку поверхности и корректного перехода между режимами, не дублируя domain rules.

## Требования

<a id="fr-ui-001"></a>

### FR-UI-001 — главные меню и начало одиночной сессии

**Предлагаемая фаза: Pre-alpha.** Игроку доступны начальный экран, одиночная игра, новая игра, создание или выбор заранее подготовленного персонажа, загрузка продолжения, настройки, титры и выход. Главное меню показывает только функции, поддержанные текущим игровым профилем. Выбор кампании/модуля на уровне UI передаётся в content-loading boundary; сами правила поиска, приоритета и допуска модуля здесь не задаются.

**Наблюдение по оригиналу:** прочитанный набор главного меню содержит Single Player, Options, Credits и Exit (F0; полный набор кнопок в exe не сверен); далее меню ведёт к новой игре или предустановленному персонажу. В запуске меню (0x541180) разные типы окна задают in-play/locked/options состояния, а открытие настроек (0x589280) в меню создаёт список модулей и отключает этот контроль в игре. Кнопки и переход в одиночную игру, создание меню персонажа (0x5446A0, 0x5446D0, 0x5446F0), ветвь создания персонажа (0x545780, 0x545870, 0x5458D0, 0x5459F0, 0x545B60), модульный control и запрет смены в игре (0x589280). В Steamwoven нет игрового menu/session flow: его Godot entry page прямо обозначен как диагностический ART inspector. [Viewer app surface](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Godot/ViewerApp.cs#L82-L103).

**Зависимости и сценарии:** персонаж, стартовая карта, настройки и content-product module admission. Проверить новый/предустановленный персонаж, отмену до старта, выбор другого модуля до входа в игру и возобновление доступного сохранения. Импорт/экспорт персонажа отдельно не предполагается. **Steamwoven:** только инструменты DAT/ART/terrain; данных меню и production UI нет. **Неизвестно:** полный lifecycle запуска оригинала и ошибки выбора модуля здесь не прогонялись.

<a id="fr-ui-002"></a>

### FR-UI-002 — игровой HUD, хоткеи и контекстное управление

**Уточнение владельца 2026-10-04:** keyboard/mouse сохраняют оригинальные действия, раскладку и семантику UI; кастомное управление и интерфейс относятся к gamepad. Подробные привязки, контексты и границы подтверждения сведены в [единый документ требований к оригинальному вводу](original-keyboard-mouse.md). WASD не управляют персонажем. Диагностические команды требуют отдельного слоя и не занимают обычные игровые клавиши.

**Предлагаемая фаза: Pre-alpha.** Во время исследования мира игрок видит состояние персонажа и доступные панели действий, управляет режимами combat/skills/spells, назначает и запускает действия из десяти быстрых ячеек и двух недавних действий, выбирает цель и получает обратную связь по наведению/контекстному действию. Клик, drag предмета, targeting и UI hotkey должны иметь определённого владельца ввода при открытых модальных экранах.

**Наблюдение по оригиналу:** функции игрового интерфейса (0x549B70–0x557CF0, 160 функций) маршрутизируют сообщения между scrollbar, hover handlers, hotkeys, активным dialog filter, combat turn и нижними кнопками, включая открытие меню через clock button и вызов spell/skill/combat panels. Запуск быстрых ячеек (0x57D840) создаёт десять слотов и два recent-action buttons, обработчик их событий (0x57DC60) обрабатывает события/перетаскивание. Компактная панель (0x5689D0–0x5695A0) рисует health/fatigue bar, но объявленный в ней hotkey component имеет пустые init/message/draw тела (F0) и не подтверждает работающую компактную панель быстрых действий. Основная обработка игрового ввода и clock/menu branch (0x54B5D0), quick slots и recent actions (0x57D840), события hotkey UI (0x57DC60), реализованный compact health/fatigue draw (0x569070), объявленный hotkey component и пустые hooks, stub-реализации hotkey hooks (0x569570, 0x569580, 0x569590, 0x5695A0). В Steamwoven нет production actor/HUD, только diagnostic world viewer и отдельный input experiment. [Ограниченная viewer поверхность](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Godot/ViewerApp.cs#L82-L165), [граница синтетической input settings модели](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Input/InputSettings.cs#L5-L47).

**Зависимости и сценарии:** UI mode stack, input mapping, combat/skill/spell targeting, предметные действия и общий message queue. Синтетически проверить назначение/замену hotkey, две recent actions, приоритет modal/dialog filter и pointer/keyboard переходы без двойной активации. **Неизвестно:** привязки и ограничения проверки по функциям оригинала уточнены в [спецификации оригинального ввода](original-keyboard-mouse.md); оригинальный runtime, локализованные ресурсы и физическое удобство требуют отдельной проверки. Кодовые UI ids сами по себе не устанавливают продуктовую раскладку.

<a id="fr-ui-003"></a>

### FR-UI-003 — режимы окон, диалог и переход между действиями

**Предлагаемая фаза: Pre-alpha.** Диалог показывает допустимые реплики и принимает выбранный ответ. Переход dialog → trade, character/follower sheet, world map, schematics, identify/repair или возврат в игровой мир открывает ровно нужную поверхность и закрывает предыдущую в правильном порядке. Открытые окна блокируют только действия, которые доменные правила запрещают; ошибка/отмена возвращает игрока в понятное предыдущее состояние.

**Наблюдение по оригиналу:** вход в диалог (0x567460) проверяет состояние участников, допускает открытие dialog, получает DLG и начинает text-conversation UI. При выборе ответа обработка реплики (0x567E30) маршрутизирует результат в дальнейшую реплику, завершение, barter, character sheet, world map, schematic, identify или repair. Смена режима интерфейса (0x551A80) ведёт стек режимов и вызывает close/open handlers. Вход в dialog и старт режима (0x567460), переходы по выбранной реплике (0x567E30), stack и обработка оконных режимов (0x551A80), dialog text options bridge (0x553320, 0x553350, 0x553370, 0x553380, 0x5533A0). Steamwoven имеет DLG reader и ограниченный headless Direct-transition runtime; это не dialog screen, NPC invocation или game UI integration. ARC-SCRIPT-005 добавил [многошаговый conversation runtime](../scripting/dialog-conversation-runtime.md) и диагностическую модальную панель разговора в AREA viewer (клик по NPC и по реплике, как в оригинале; клавиши не перенаправляются); переходы в trade/sheets/world map и др. показываются заблокированными, без эффектов. [Текущий экран viewer](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Godot/ViewerApp.cs#L82-L103), [изолированное diagnostic display lab](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/input/display-ui-validation.md#L3-L16).

**Зависимости и сценарии:** [story/dialogue runtime](../requirements/README.md), DLG data, barter/items, character/social state, target identity и modal focus. Проверить действие ответа → каждый экран и закрытие/отмену с восстановлением активного режима. UI не повторяет валидность реплик, квестовые последствия и экономические формулы. **Неизвестно:** коды переходов на неполных/ошибочных ветках и полная DLG/SCR семантика требуют отдельной проверки.

### FR-UI-004 — инвентарь, персонаж, журнал, карта, записи и спутники

**Предлагаемая фаза: Pre-alpha для доступа к ключевым экранам; полный контент/все подрежимы Later.** Игроку нужны игровые панели для своего и доступного чужого инвентаря, экипировки/персонажа, торговли и loot/steal/repair; отдельные действия открывают logbook, world map/travel, книгу/заметку, найденную технологическую схему и список спутников с командами. Каждая панель передаёт предметные, персонажные, мировые и сюжетные изменения соответствующему владельцу правил.

**Наблюдение по оригиналу:** открытие инвентаря (0x572240) обслуживает несколько разных инвентарных режимов; открытие листа персонажа (0x5597C0), журнала (0x53F020), карты мира (0x560760), записанного объекта (0x56BB60) и переключение схемы (0x56D130) создают профильные экраны; схематика, записанный объект или ответ dialog имеют отдельные callers. Фильтр сообщений окна спутников (0x56A9D0) передаёт команды спутника в order/target, inventory/barter и character views. Инвентарь и режимы (0x572240, 0x572340, 0x572370), character sheet open (0x5597C0), logbook и world map (0x53F020, 0x53F090, 0x53F0D0, 0x53F0E0), world map open (0x560760, 0x560790, 0x5607E0), written objects (0x56BB60, 0x56BC00), schematics (0x56D130), follower actions/callers (0x56A9D0). Steamwoven имеет только diagnostic scenes/labs; main HUD, character/inventory/trade/journal/map/dialog panels не реализованы. С ARC-UI-007 AREA viewer открывает по `C` диагностический лист персонажа героя сессии только для просмотра; открытие/закрытие, отказ для мёртвого PC и показ значений сверены с оригинальным exe ([viewer](../rendering/terrain-viewer.md#character-sheet-arc-ui-007)); с ARC-MAGIC-008 у листа есть страница заклинаний оригинала (16 школ, ранги, подсказки, `+`/`−` через путь очков, [viewer](../rendering/terrain-viewer.md#spells-page-arc-magic-008)). С ARC-UI-008 клавиша `L` (клавиша оригинала, строка [LB1](../research/ledger/ui-audio.md#logbook-arc-ui-008)) открывает диагностический журнал с вкладками слухов и заданий ([viewer](../rendering/terrain-viewer.md#logbook-arc-ui-008)). [Viewer class surface](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Godot/ViewerApp.cs#L7-L17), [synthetic UI lab boundary](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/input/display-ui-validation.md#L63-L65).

**Зависимости и сценарии:** [предметы и экономика](items-economy.md), [персонаж и навыки](characters-skills.md), world map, dialog/story и companion domains. Для каждого экрана проверить открыть/обновить/закрыть, удержание допустимой selection state, переход в зависимый режим и отсутствие повторного вызова gameplay mutation. **Неизвестно:** полное содержимое записей и оригинальных UI labels здесь не изучалось.

### FR-UI-005 — выбор реплик, сообщения, tooltips и плавающий текст

**Предлагаемая фаза: Pre-alpha.** Игрок понимает наведённый объект/действие, видит выбранные dialog options, сообщения о результате, статусные text bubbles и относящиеся к объекту floating notices. Подсказки не закрывают доступные варианты без причины, текст не остаётся привязан к старой позиции объекта, а настройки длительности/видимости применяются согласованно. Длинные строки и окно dialog должны иметь предсказуемое перенесение или прокрутку.

**Наблюдение по оригиналу:** функции вариантов диалога (0x4C9280–0x4C9BE0) рисуют до пяти dialog options, подсвечивают их мышью и выбирают по нажатию; по чтению (F0) ветвь красного цвета текста не используется, а горизонтальные границы вариантов не ограничиваются. Функции текстовых пузырей (0x4D5B80–0x4D67F0) рисуют bubbles над объектами и удаляют их по таймеру; функции плавающего текста (0x4D4E20–0x4D5DC0) ведут объектные текстовые списки и плавно меняют расположение/opacity, уровень и скорость берутся из настроек. Dialog option rendering and mouse selection (0x4C9720, 0x4C9810, 0x4C9A10), object bubbles and expiry (0x4D5EB0, 0x4D5F10, 0x4D5FE0), floaters and rendering (0x4D5190), floater creation and level controls (0x4D5310, 0x4D5450). В Steamwoven нет production game text/floater layer; synthetic display lab checks independently authored layout geometry only. Диагностическая панель ARC-SCRIPT-005 показывает decoded реплику NPC и до пяти пронумерованных вариантов с переносом строк. ARC-UI-005 добавил в AREA viewer подсказку при наведении (имя объекта, как его даёт осмотр объекта оригинала (0x441B60), выбор как у оригинала с пропуском `OF_CLICK_THROUGH`) и курсор действия левого клика (project policy: оригинальный курсор от цели не меняется), см. [viewer](../rendering/terrain-viewer.md#hover-tooltip-and-action-cursor-arc-ui-005); bubbles и floaters не реализованы. [Именно synthetic UI scope](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/input/display-ui-validation.md#L5-L16), [не production UI decision](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/input/display-ui-validation.md#L63-L65).

**Зависимости и сценарии:** общий UI text layer, локализация, font metrics, viewport anchors, dialogue log, text-speed/float settings. Проверить длинные многострочные ответы, узкое окно, изменение scale, закрытие реплики, перемещение/удаление исходного объекта и выключение floating notices. **Неизвестно:** фактические оригинальные шрифты, весь clipping и полнота keyboard/gamepad доступности не оценивались.

<a id="fr-ui-006"></a>

### FR-UI-006 — доступные игровые, видео, текстовые и аудио настройки

**Предлагаемая фаза: Pre-alpha для gameplay и громкости; Later для дополнительных display/input controls.** Настройки должны разделять постоянные предпочтения пользователя и состояние текущего сохранения. Профиль настроек оригинала (F0) включает difficulty, violence filter, combat mode, auto-attack/weapon-switch, run и follower skill options; brightness, text duration, floating text/speed и combat taunts; отдельные effects, voice и music sliders. Для современного проекта также нужен согласованный экран выбора display mode, масштаба, управления и повторного назначения клавиш, если эти функции входят в принятый продуктовый контракт.

**Наблюдение по оригиналу:** таблица контролов настроек содержит три набора game/video/audio controls; module selector отключается в игре. Brightness проходит из настройки в gamma API. Три volume sliders хранят значения в настройках; инициализация звука (0x41AA30) регистрирует их callbacks, которые обновляют эффекты, голос и музыку. Три таблицы и конкретные контролы, инициализация выбранной вкладки и module guard (0x589280), brightness binding (0x4BE0B0, 0x4BE0E0, 0x4BE0F0), реальные volume-slider get/set callbacks (0x589960, 0x589980, 0x5899A0, 0x5899C0, 0x5899E0, 0x589A00), регистрация и применение volume callbacks (0x41AA30), обновление уровней каналов (0x41C8A0, 0x41C8B0, 0x41C920, 0x41C930, 0x41C970, 0x41C980), settings file read/write (0x438B50, 0x438C20). Проверенный options table не содержит resolution/window mode или keybinding editor; это не исчерпывающий поиск любого input path. В Steamwoven есть только отдельная `InputSettings` модель joystick deadzone/sensitivity/camera inversion; это не игровые options и не remappable keyboard bindings. [Input settings codec](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Input/InputSettings.cs#L5-L47), [UI lab прямо оставляет game settings/UI за границей](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/input/display-ui-validation.md#L63-L65).

**Зависимости и сценарии:** settings persistence, platform display/input services, audio mixers, character auto-level policy ([персонажный домен](characters-skills.md)). ### FR-UI-007 — адаптивная композиция и доступность окон

**Предлагаемая фаза: Pre-alpha для современной целевой платформы.** Игровые экраны должны сохранять доступ к важным кнопкам, спискам и тексту при разных размерах окна, high-DPI и выбранном масштабе. Окна не должны заслонять важные игровые данные; прокрутка, keyboard focus, cursor position и gamepad focus должны иметь явные правила. Это project UI policy и не утверждение, что оригинальные экраны были responsive.

**Наблюдение по оригиналу:** экраны рассчитаны на базу 800×600 (F0); смещение элементов относительно оконной геометрии и чтение HighRes-конфигурации (Width/Height, Windowed, scroll settings, intro/logos) сопоставленных функций в оригинальном exe не имеют. Изменение размера библиотеки игры (0x4025C0) передаёт resize callbacks модулям. Это legacy positioning infrastructure, а не проверка всех экранов на современных размерах. В Steamwoven display lab проверяет synthetic logical layouts, а не production menu/game surfaces и не физическую читаемость. [Заявленный synthetic boundary](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/input/display-ui-validation.md#L28-L30), [не production UI или физическая сертификация](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/input/display-ui-validation.md#L49-L65). Принятая project direction требует modern resolution/high-DPI/scalable UI и first-class gamepad; это политика продукта, а не вывод из оригинала. [Architecture direction](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/architecture/decisions.md#L10-L15).

**Зависимости и сценарии:** viewport-independent simulation, text and input focus contracts, display settings. Проверить production menu, dialog, inventory и save list на целевых крайних aspect ratios, масштабах и клавиатурном/gamepad фокусе, отдельно снять human visual/physical-device evidence. **Steamwoven:** synthetic lab имеет ограниченную layout verification; production UI integration и physical readability не покрыты.

**Отдельный camera pan.** Прокрутка содержимого меню и движение world viewport — разные намерения. В оригинале есть keyboard-arrow и mouse-edge callers; запуск прокрутки (0x40E0A0) учитывает настройки скорости/дистанции и в выбранной limiter-ветви Perception; player load/move обновляет центр (keyboard caller (0x401560), mouse-edge/keyboard handler (0x401560, 0x401F50, 0x402010), camera/limit policy (0x40E0A0), viewport/listener update (0x40E630, 0x40E890, 0x40E8A0, 0x40E8B0), PC load (0x40D7C0), PC move (0x444270)). Принятый modern gamepad/follow/zoom contract отдельно описан в FR-PRODUCT-003; эти Legacy handlers не доказывают его реализацию. Предлагаемые сценарии: pan/stop, объявленный distance-limit и центрирование без изменения actor state; mouse-edge режим и точный original лимит требуют собственного решения/проверки. Текущий diagnostic pan не является production original-limit policy.

### FR-UI-008 — in-play menu, modal guard и согласованная пауза

**Предлагаемая фаза: Pre-alpha.** Игрок может вызвать меню из игрового интерфейса. Меню скрывает игровую рамку при необходимости; в запрещённых действиях остаётся в безопасном locked state. Пауза блокирует именно симуляцию мира согласно time policy, но меню, ввод, fade и необходимые интерфейсные/реальные события остаются отзывчивыми. **Наблюдение по оригиналу:** при запуске non-options menu запуск меню (0x541180) вызывает внутренний pause-count helper и скрывает main interface; clock button выбирает обычное или locked in-play меню в зависимости от dialog/world-map/combat-turn guard. Menu open/pause-count branch (0x541180), clock button locked/open decision (0x54B5D0), pause count helpers (0x45B320, 0x45B340, 0x45B360), time domains during pause (0x45B370). См. В Steamwoven нет игрового screen/mode stack или pause state; viewer playback pause относится только к inspector timeline. [Отдельный диагностический timeline](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Godot/ViewerApp.cs#L104-L158).

**Зависимости и сценарии:** единый clock/pause owner, dialog/combat turn states, UI stack and real-time event policy. Проверить opening/closing каждого разрешённого menu state, запрет на ходе чужого turn, неускорение мира от UI redraw и отзывчивость menu/input во время паузы. **Неизвестно:** полный набор причин внутреннего pause gate и оригинальный executable response не подтверждены независимо.

### FR-MEDIA-003 — эффекты, голоса и музыка с независимыми настройками

**Предлагаемая фаза: Pre-alpha.** Игра предоставляет различимые effects, dialogue voice, ambient and music channels with independent user-facing volume controls. Voice can start/stop with the dialogue speaker; sound effects can be triggered by in-world actions; a failed audio backend must not invalidate unrelated world state. **Зависимости и сценарии:** platform audio service, sound resource profile, options persistence, dialogue lifecycle, combat and item/world events. Check muted/independent channels, missing device/startup, voice cancellation on dialog close (в оригинале голос после закрытия доигрывает, SN22 ARC-RES-052), and no simulation corruption when playback fails. **Неизвестно:** decoded file format set, actual device support, latency and cross-platform quality remain untested.

### FR-MEDIA-004 — ambient/positional звук и переход схемы сектора

**Предлагаемая фаза: Pre-alpha для базовой карты и голосовых/effect cues; полное покрытие типов Later.** Ambient/music scheme follows the active map/sector, transitions without stuck or duplicated tracks, and resolves combat music back to the active world scheme. Sector change caller (0x4F2330), scheme switch/fade (0x41BD50), spatial attenuation and panning (0x41B420), combat music and restore (0x41C4D0, 0x41C5A0), surface/equipment footstep selection (0x4F0ED0). ### FR-LIFECYCLE-001 — запуск, новая сессия, продолжение последнего сохранения и выход

**Предлагаемая фаза: Pre-alpha.** Starting the application loads the declared content profile, initializes presentation and shows an optional startup sequence before the menu. New game enters a selected module and character; continue loads a selected/latest valid save; returning to menu or quitting leaves the previous save intact. Startup, module-loading and movie failures need an actionable state and defined recovery/shutdown sequence.

**Наблюдение по оригиналу:** main (0x401000) loads the default module and UI module data, may play intro movie 8 (the condition is not checked in the executable), then calls the main menu handler. Read without an executable check (F0), a module failure exits without a graceful shutdown or a distinct error exit status, so the original does not demonstrate robust recovery. Latest save selector sorts save entries by date; last-save window loads selected metadata then delegates to common load handler. Startup ordering and failure exits (0x401000), last-save UI path (0x544440), latest save lookup (0x403850, 0x4038C0). In Steamwoven no game session bootstrap or continue menu exists; diagnostic ViewerSession opens/closes selected archive data only. [Viewer-only open/close lifecycle](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Godot/ViewerSession.cs#L30-L54), [archive close](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Godot/ViewerSession.cs#L101-L109).

**Зависимости и сценарии:** [content-product](content-product.md), [persistence model](../architecture/decisions.md#architecture-direction), UI lifecycle and error domain. Test cold start, intro disabled, missing video, failed default module, first-run with no save, continue and normal quit with state preservation. **Неизвестно:** this inspection did not establish all current-app OS startup/shutdown details for Steamwoven or original executable.

### FR-LIFECYCLE-002 — сохранение, список, overwrite, delete и preview

**Предлагаемая фаза: Pre-alpha.** Player-facing save manager lists saves with readable description, character and enough location/time context to distinguish entries. It supports create, overwrite after confirmation, load, delete after confirmation, and continue from the latest valid save; protected automatic saves cannot be deleted through the normal delete action. UI must show save/load progress and specific failure rather than claiming success.

**Наблюдение по оригиналу:** save action selects or allocates a slot, asks confirmation before overwriting, calls the game library save (0x403030) and reports success/failure. No save operation was run here.

<a id="fr-lifecycle-003"></a>

### FR-LIFECYCLE-003 — согласованный save payload, schema и ошибка загрузки

**Предлагаемая фаза: Pre-alpha.** Save contains one coherent authoritative game state, including every required domain and UI state at a clear boundary. New game/save schema version, module identity and any profile compatibility are checked before mutation. Truncated, corrupt, incompatible or partially restored saves stop safely, identify the failure and preserve the previous usable session/save. Loading must not silently mix modules or leave partly replaced global state.

**Наблюдение по оригиналу:** the game library save (0x403030) writes version 25 and invokes per-module serializers with `0xBEEFCAFE` sentinel after each; it separately invokes extra UI save callback, writes metadata and archives `Save\\Current`. The game library load (0x403410) clears/restores that working directory, reads a version field but does not compare it at top level, invokes module loaders and checks sentinels. Main-menu caller checks save metadata version==25 before the load; after success it sets current module name from metadata. Do not infer that every module validates compatibility or that rollback is transactional. Module serialization/save payload (0x403030), load reads version and module sentinels (0x403410), caller metadata check and module identity restore (0x5432B0), UI serializer registration and module list, game library save-module registry. Steamwoven has no game save schema/store/module restore implementation; its versioned input settings JSON is a separate config preference codec. [Diagnostic settings codec only](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Input/InputSettings.cs#L23-L47).

**Зависимости и сценарии:** all domain save owners, stable schema/profile migration, module admission and backup/error policy. Test field truncation, wrong version/module, sentinel mismatch, module loader failure after earlier loads, retry into known-good save and proof old save remains intact. **Неизвестно:** complete per-module load callback validation, source save variants and original compatibility matrix were not audited.

<a id="fr-lifecycle-004"></a>

### FR-LIFECYCLE-004 — пользовательские настройки против save-bound state

**Предлагаемая фаза: Pre-alpha.** Audio/video/input preferences and interface options persist independently from per-campaign world state; UI indicates whether a change applies immediately or after relaunch. Resolution/window/high-DPI, key remapping, controller options and text/accessibility values need validated range, defaults, reset-to-default and graceful fallback if unavailable on a platform. Domain state such as map, inventory, story flags and game clock belongs in the save instead.

**Наблюдение по оригиналу:** settings load (0x438B50) parses key-value settings, settings save (0x438C20) rewrites changed preferences and is tied to game library lifecycle. Settings path is `arcanum.cfg` or `worlded.cfg`; a `HighRes/config.ini` reader (resolution/windowing/scroll/intro/logo keys) has no matched function in the original executable and is not the options screen. Settings configuration parsing and writeback (0x438AE0, 0x438B00, 0x438B50, 0x438C20), settings-path setup (0x4020F0), init path (0x401000). Steamwoven has project-owned input settings codec, but that covers bounded camera/actor tuning; the documented display UI lab is separate and explicitly does not persist final product/game preferences. [Input settings values/validation](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/src/Arcanum.Input/InputSettings.cs#L5-L47), [UI lab boundary](https://github.com/Simarglok/arcanum-steamwoven/blob/b1245e59c585c7b7b03dd0b764e2d3e31d0f89ae/docs/input/display-ui-validation.md#L63-L65).

**Зависимости и сценарии:** settings store, platform capability checks, user input and save module ownership. Change music volume and world setting separately, restart, load earlier game save, reset preferences and confirm only expected category changes. **Неизвестно:** exact original settings-file validation/atomic write guarantees are not established by these bodies.

Single-player import/export support remains unknown; do not assume it belongs in Pre-alpha. **Исследовано 2026-10-27 (ARC-RES-072, exe F2):** [мультиплеер оригинала](../research/multiplayer-evidence.md) — до 8 игроков, хост применяет правила и рассылает состояние по своему TCP поверх WinSock (порт 31435, поиск в LAN по UDP 31434), WON только как лобби; сетевым считается модуль с файлом `mp.txt` (есть у `Vormantown`, нет у `Arcanum`); экспорт персонажа из одиночной игры — скрытая клавиша X в окне персонажа, файл `.mpc` без вещей и спутников.
