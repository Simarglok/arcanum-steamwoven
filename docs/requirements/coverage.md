This table is the **status of the requirements**. A requirement's description, the original behavior, acceptance and research stay in the domain documents; where the current status differs from the "Steamwoven" field of a domain document, this table is correct. The requirement rows live in the [section](#sections) files, one per domain document. A task that changes a requirement's coverage updates its row in the section file and the section's counts in the summary in the same PR ([rule](../workflow/tasks.md#functional-requirements)).

## Status scale

| Status | Meaning |
| --- | --- |
| Implemented | The requirement's behavior works in the game path (AREA viewer, map mode) on every map the viewer opens, and is covered by the task's checks. Only reservations about parity with the original and about the main map are allowed; the row names them. |
| Partial — in the viewer | Part of the behavior works and is visible in the viewer; what is missing is named in the row. |
| Partial — no host | The data or rules code is merged and covered by tests, but is not yet wired into the viewer (no host, UI or caller). |
| Researched | There is research of the original (sometimes also a data read), but no code that implements the requirement itself; related code may be named in the row. |
| Not started | Neither code for the requirement nor targeted research; related mentions are named in the row. |

"Viewer" is the diagnostic `area` Terrain Viewer: Crash Site outside and the cave, the [map mode](../rendering/area-map-mode.md) for 80 interiors and the main world map in windows (`./arcanum map NAME`; since ARC-RENDER-028 `./arcanum area` is the map mode of the main map at Crash Site). There is no game, main menu or game-build export. Parity with the original `Arcanum.exe` is checked against the [verification ledger](../research/original-verification-ledger.md) and the [function register](../verification/README.md); the "checked against the exe" note refers to rules, not to the picture on screen.
