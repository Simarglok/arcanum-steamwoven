## Method

Behaviour comes from the retail executable (`Arcanum.exe` 1.0.7.4, SHA-256
`9bd80511…78d52`), read statically with `llvm-objdump` per the
[original executable check](../research/original-executable-check.md). By the owner's
decision of 2026-11-04 this slice ran in a cloud clone: the owner's unchanged executable was
copied from the Mac installation into the session's temporary container (never into git),
its hash and `Version.txt` (1.0.7.4) were checked there, and it was read from that copy. Six
readers in three question groups (the run table and how a goal starts; priorities,
interrupts and the end of a run; who starts goals: input, scripts, AI and engine), two
readers per group, each of which saw only the questions and the starting addresses from the
project's records (method step 6). A row at **F2** has two readings that agree; **F1** has
one reading; a disagreement is written in the row. Everything is read from the executable
unless marked **(inference)**; **(partial)** marks code read only in part. Four points where
the readers differed were settled by a third reading of the disassembly and are named in
their rows (the bottom insert in GS14, the main walk's retarget in GS14, the Shift flag 0x100
in GS6, the back-off run's gate in GS31). The goal names are the executable's own
(table 0x5A164C), object fields come from its field table (0x59BEA8), and the descriptor
table 0x5B03D0 was read entry by entry from the file image. The network branches are noted
where they cut across a row and not followed (slice R6). Steamwoven facts come from the
[model map](steamwoven-model.md) (M1, §6), `AreaAiHost` and `Simulation/Ai` on `origin/main`
c7e81acf.

Terms: a **run** is one slot of the animation module's run table: one goal stack driven by
Anim events (kind 1, clock 2, [TL40](original-time-loop.md#7-turn-based-rounds)). A **goal**
is one frame on that stack; the **bottom** goal is the one the run was started with and the
**current** goal the top one. A **level** is the strength of an interrupt, compared with a
goal's **priority**.

## Answer

- **One goal system for everything that animates.** The hero, NPCs, doors, projectiles,
  spell missiles, eye candy and burning scenery all run goals in one table of 216 runs,
  stepped by one handler. There is no separate PC machine: the hero's walk, attack, talk,
  use, pickup, throw, skill and cast are goals of the same 87 types the AI uses, with the
  same nodes, priorities and interrupts (GS1–GS3, GS25–GS32).
- **One main run per object, overlays beside it.** Nothing stops an object from owning
  several runs. Fifteen goal types carry a no-interrupt flag (eye candy, floating, door
  attempts, friendly casts, the secondary cast animation, spread out): they start beside the
  main run and survive its interrupts. Everything else replaces what runs (GS3, GS9).
- **Priority decides replacement as well as interruption.** Every goal type with a
  descriptor (85 of 87) has a priority 1–5. Starting a goal interrupts all the object's runs at a level (the new goal's priority,
  or a fixed 3, 4 or 5 chosen by the starter); a run whose current goal may not be
  interrupted at that level refuses, and the start fails. So a walk (2) cannot replace an
  attack (3), an attack cannot replace a spell release (4), and nothing but level 6 stops
  dying, a projectile or a knockback (5) (GS12, GS13, GS16).
- **Five effective levels.** 0–1 stop nothing; 2 stops idles and movement; 3 (and 4, which
  acts the same) stops every ordinary action; 5 also stops spell releases and unconceal; 6
  stops everything, overlays included. Round start, new orders and AI decisions use 3; the
  AI tick of a far critter, stuns and the world map use 4; death, knock-down, peace,
  teleport and leaving the party use 5; the end of a run, a failed AP payment and a map
  change use 6 (GS18–GS20).
- **An interrupt always ends the whole run**, running the end node of every goal on the
  stack; only the stepper's own end of a run calls the turn-based hook and the idle
  restart, so a run stopped from outside never triggers the next AI decision or a fidget
  (GS22–GS24).
- **The hero's click builds goals itself.** The object click (0x54ED30) builds attack, talk,
  use, loot, pickup, throw and trap-walk goals directly, without the start gate and without
  the AI's attack and pickup starters; tile walks, item use, skills, throws and casts go
  through the same starters as the AI. In a round the click is taken only while the hero is
  idle (GS25–GS28).
- **Talking, looting and doors are goals.** Each approaches, then acts in its last node: the
  dialog opens, the loot window opens, the use script fires, or a door's own run plays the
  opening, waits 1.5 s in goal 72 and closes (GS29).
- **Scripts start few goals.** Perform animation, walk to, run to, use item, steal, get up
  and the casts; attack, follow and flee reach goals only through the AI (GS30).
- **For Steamwoven.** The hero's actions are viewer goals beside the AI's `AiGoalRun`, which
  holds one run per NPC of the shown map with priorities for 26 goal types, no overlays, no
  alias table and an interrupt helper that always succeeds; doors, projectiles and eye candy are
  separate viewer objects, not runs. Details sit in the rows; the gap register is G1's.

## Corrections to earlier records

Older records that this reading contradicts or completes. None is edited here, because
parallel audit slices work in the same files; the gap register (G1) or a docs-only fix should
correct them.

- TL40: the no-interrupt goals are 15, not 13: the fire-damage eye candy 75 and 76 carry the
  flag too, so eight eye-candy goals have it, not six (GS9); the flag is read on the current
  goal and ignored at level 6, and a game reset runs no end nodes (GS16).
- TL42 and the brief's starter list: 0x4357B0 starts the stun (goal 57 `ag_animate_stunned`),
  not the knock-down; the knock-down starter is 0x435A90 (goal 62) (GS13).
- TL43's census line "the first frame of a new goal is queued at 0 ms (0x44D730)": 5 ms, or
  1 ms straight into the live list for a non-current owner in a round (GS7; TL41 has it right).
- PS15 (a precision, not a contradiction): a goal frame has 21 parameter slots in memory, slot
  20 being the goal's sound handle, but the save writes that slot as −1, so the file's twenty
  saved parameters stand; the run's two trailing 8-byte values are +0xCF8 (an unread dword and
  the pace at +0xCFC) and the next event's due time (+0x18) (GS1, GS5).
- AG1: the step word also has bit 0x1000000 (keep the per-goal run flags on a pop) and
  0x2000000 (reset the path) (GS6).
- AG4 and AG7: the "frame flags 0x4 and 0x8" of the action frame are run flags at +0xC, not
  bits of the goal frame (GS6).
- EX22: the back-off run starter 0x433C80 calls the movement gate 0x4339A0, so the back-off
  run is gated in a round (only the start gate 0x4348E0 is not called) (GS31).
- TH9: the fidget start 0x435BD0 accepts the hero (type 15) as well as NPCs (GS28).
- The [AI execution](../research/npc-ai-execution.md#1-perform-and-its-actions) starters table:
  a second dead starter, skill conceal 0x436370 (goal 35) (GS32).
- functions.csv on 0x434F80 ("an equal goal already queued … read as an equal throw in the
  object's one run"): the original walks every run of the object (GS4).
