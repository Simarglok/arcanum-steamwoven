# High-level dependency roadmap

This is a product dependency map, not a task queue or authorization to implement a milestone. Active work items, accepted scope and dependencies come from the owner's explicit requests ([task workflow](../workflow/tasks.md)). The [status catalogue](status.md) and [requirements register](../requirements/README.md) share the 2026-10-09 audit baseline through PR #54. The [vision](vision.md) records accepted product direction. Later stages below are proposed dependencies, not dates or approval of the full catalogue.

| Stage | Current delivered scope | Next dependency / observable gate |
| --- | --- | --- |
| Read original resources | Bounded DAT/ART/MES/sector/static/mobile/prototype readers, selected SCR/DLG consumption, explicit source identities and original-data checks. | General precedence/discovery/format variants require their own research. Preserve independent MIT implementation and synthetic public fixtures. |
| Exterior Data polygon | DATA009 publishes complete selected exterior core/context metadata and selected body/terrain chains. | RENDER007 must consume that API and demonstrate all admitted exterior visuals, coordinates/scale/mirror/ordering/resource lifetime. Data completeness alone does not validate rendering. |
| Finite actor/control diagnostic | HumanFixed, exact headless movement, WORLD003 narrow real-data cardinal/diagonal assessment, Follow/Manual and WORLD zoom/settings are merged. | Preserve finite regression while adding independently admitted world coverage. Full-area registry/HP/state/neighbor frontiers remain NOT_READY; a larger picture must not silently authorize movement. |
| Controls and debug visibility | Original keyboard/mouse requirements exist; custom gamepad movement/zoom implemented in diagnostics. | Deliver INPUT001/RENDER008 and GPAD005 within their accepted card scopes. Original click-route needs a route consumer; quick slots/semantic targeting need action/state services. Physical Xbox UX belongs to owner testing. |
| Dialog/state foundation | DLG reader/one Direct edge, computed NPC entry bridge and standalone GF owner/adapters are merged. Reply/effect and negative IN contracts are research. | Connect only supported state ports/grammar and explicit conversation lifecycle. GF in DLG is still Unsupported; inventory/IN, reaction/RE, real LF/quest/rumor owners, text/UI and world interaction remain separate seams. |
| Time/light foundation | Raw clock/light research and proposed normalized clock contract are merged. WORLD004 is outside this audit's merged baseline. | Deliver admitted headless clock policy before hourly scheme/ambient/emitters; keep movement time, ART time and gameplay time distinct. Actual day/night rendering and gameplay consumers require separate checks. |
| Audio foundation | Board has research, synthetic lab, original loader/lab and subsequent music/voice/positioned-SFX work. None is merged on this baseline. | Bound resource/codec/lifetime contracts, then audible synthetic/original checks; world/music/voice/footstep integration separately. An audio lab is not all game audio. |
| Cave and connector | Separate cave/endpoint inventory exists; exterior snapshot contains a numeric endpoint. | Resolve destination loading/rendering and trigger semantics, transition/arrival/return and state lifetime. A potential endpoint pair is not a working transition. |
| Small playable slice | Foundation components exist, but no connected playable scenario is delivered. | Agree a concrete scene/actor/NPC/dialog/transition and required day/night/audio/input cases; demonstrate loading → admitted movement → interaction/conversation → cave/return with preserved state. Keep full-game catalogue distinct from agreed pre-alpha acceptance. |
| Gameplay expansion | Character/equipment/combat/AI/quests/navigation/persistence remain largely unimplemented. | Research and deliver bounded behavior/testable consumers incrementally; reuse FR IDs and record unsupported branches, intentional changes and original-runtime comparisons. |
| Compatibility and presentation expansion | Legacy diagnostics and macOS are the current proven development boundary. | Validate supported platforms/mod profiles on an agreed functional slice; later upscale original directions/frames one-to-one and implement shared-state Legacy/HD toggle. Additional frames/directions/3D require separate resource/technology decisions. |

Independent headless/Data/research work can proceed while graphical validation is unavailable where its accepted contract permits. GUI/export/device gates remain required for scopes that need them; a locked Mac is not proof of failure or completion and does not justify substituting unrelated green checks.

Planning starts from the FR/domain coverage, actual merged code/history and open PRs, not the number of finished tasks. Each new task should identify supported requirements and update their implemented scope as an output. Task creation, prioritization and project delivery/merge authority remain in the user request and current project workflow; this document adds no extra restriction.
