Source: wave 3 (groups G and I) of the [function audit plan](../function-audit-plan.md#5-recommendation) (ARC-RES-105), the first wave read from the Ghidra text export (`research-private/ghidra-export/c/`, Ghidra 12.2, ARC-DEV-377 and ARC-DEV-379; [how it was made](../../workflow/toolchain.md#ghidra-text-export-arc-dev-377)) instead of `llvm-objdump` listings. Read on 2026-11-11 on the owner's Mac (`Arcanum.exe` 1.0.7.4, SHA-256 `9bd80511f8663a41a25a20a701959e394e0065e4ffc68a8dc69fe19c23678d52`). **Docs-only: no code changed, no registry row added and no mark written**; the root check run for it is `FunctionRegistryTests.NoTrackedFileNamesTheReconstruction`. ### The groups

The earlier slices (A 0x40-0x41, B 0x42-0x43, C 0x44-0x45, D 0x46/0x49/0x4A, E 0x4B-0x4C, F 0x4D-0x4F, H1 0x50-0x54, H2 0x55-0x59) each took the [census](../../verification/census.csv) rows of their band. The census lists 5,815 function starts; the Ghidra export lists 6,717 functions with a C file (6,711 decompiled and six two- or three-byte fragments that failed) and 139 thunks without one (`data/functions-all.tsv`). Wave 3 takes the functions the export has and the census has not, so that every function of the export has a state:

- **Group G**: every export function in 0x470000-0x49FFFF that is not a census start (0x47 and 0x48 have no census row at all, 0x49 had 30), and every other export function in 0x400000-0x4FFFFF that is not a census start. 683 functions (682 with a C file and one thunk).
- **Group I**: every export function in 0x500000-0x59FFFF that is not a census start. 359 functions (264 with a C file and 95 thunks).
- **Together 1,042 functions**, none of which had a registry row. The 44 census starts that have no C file are [finding GI-1](#findings-of-wave-3). No earlier document named the groups; the thread's definition is written down in the [verification README](../../verification/README.md#function-triage).

Where the 1,042 come from: of the 946 with a C file the export's own origin file says 834 were created by the gap scan of ARC-DEV-379 (code bytes no analysis covered), 50 are pointer targets the gap scan added, 48 are Ghidra's own analysis and 14 its follow-up; the other 96 are thunks. They are the starts the census scan did not find, so most are, by construction, not reached by any direct call, data pointer or prologue the census saw.

### How it was read

- **96 thunks were sorted by script** from `data/functions-all.tsv`: 2 jump to another function of the executable (class `forwarder`) and 94 to an import or library address (class `crt`, mostly the C runtime's import stubs at 0x59xxxx).
- **289 functions were sorted by script.** Group G holds 309 functions inside the giant switch that fills a prototype (0x468930 to 0x49A289, [PX4](../prototype-extraction.md)); 289 of them call nothing but the object field setters (0x406D40, 0x407340), the art id builders (0x5043C0, 0x504290) and the field getters (0x406CA0, 0x4078A0), so they are class `prototype-fill`. The other 20 call something else and were read like the rest.
- **657 functions were read** by 19 readers (Sonnet), each taking a chunk of about 33 KB of decompiled C with the repository's earlier readings at hand: body, callees, strings and globals of the export, the disassembly listing when the decompiler was unclear, and our code found by searching `src` and `docs` for the address. A reader gave one state per function and compared the behaviour of every function we implement with our method. No second reading was made, so every row is **F1**.
- **No decompiled text, listing or game string is stored**: the CSV and this section keep addresses, the readers' own short descriptions and counts of callers and pointers (from the export's `data/functions-all.tsv` and `raw/pointers.tsv`).

### Rules of this reading

- **The states map onto the registry's** as in [slice H2](census-triage-h2.md#rules-of-this-triage): not relevant has a reason class and no row, read and implemented is `full` or `partial` with an `[OriginalFunction]` mark, read and not implemented is `not implemented`. Because this task is docs-only the rows and marks wait for T1; the CSV is the record until then.
- **Strict implemented.** A method of an assembly the registry test loads, or of the viewer, must do what the function does for one part of its callers; a property, a constant or inline code does not count.
- **Dead is not missing.** A function with no direct caller and no pointer holder in the export is reported as such (`direct_callers` and `pointer_holders` in the CSV). That is a weak proof of dead code: a call through a register, a computed jump and a mid-function split (the tails of 0x467440, 0x4EAE90, 0x4F7440, 0x57AEB0, 0x4C8E60) are invisible to it; the rows where it matters are task T5.
- **The export's own caveats** (see its README): 0x406D40 is a plain field setter (an older export cut every function after a call to it); the decompiler's operand widths and wraps are guesses, so a rule that hangs on one was checked in the listing.

### Findings of wave 3

The audit changes no behaviour. The first four findings are about the audit itself, the others about the code.

- **GI-1 44 census starts have no C file.** 44 of the 5,815 census starts are not rows of `c/index.tsv`: 43 are Ghidra thunks (listed in `data/functions-all.tsv` as kind `thunk` with their target) and 0x434947 lies inside 0x4348E0: 41B2D0, 434947, 4384F0, 43AA60, 457100, 459F50, 49CC50, 4A4EC0, 4A4ED0, 4A4EE0, 4A4F80, 4A4F90, 4B9E20, 4BAC20, 4BE1B0, 4CC210, 4D0F40, 4D3320, 4D5090, 4D5150, 4D5DB0, 4D5E80, 4E3020, 4E9930, 4F8340, 51F250, 53A290, 53A296, 53AB20, 53E5EC, 54EB50, 553370, 55EFE0, 55F0D0, 5673A0, 56EBF0, 56EF40, 57BB40, 57CAA0, 57CE00, 5826C0, 585BA0, 593252, 595898. Twenty-one of them have registry rows (49CC50, 4A4EC0 to 4A4F90, 4D0F40 to 4E9930, 4F8340, 51F250, 53A290 to 54EB50). They are not lost, but a reader who works from `c/` alone does not see them; the census and `functions-all.tsv` are the lists that have them. The 139 thunks are these 43 and the 96 of wave 3.
- **GI-2 The new starts are mostly not functions or not reached.** Of the 946 with a C file, 376 are not code or case blocks of the prototype fill (87 `not-code` plus 289 `prototype-fill`): padding, jump tables, index tables and mid-instruction bytes decoded as code, and the case blocks of one switch. Of the 657 read functions 620 have no direct caller and no pointer holder in the export, 596 of the 626 not relevant ones. The export would be easier to use if the 87 non-code starts were removed or merged into their neighbours (T2); the CSV marks each with its class and the reading says which neighbour it belongs to.
- **GI-3 Only 31 of the 657 read functions carry a rule**, 17 not implemented and 14 implemented; all the others are class accessor, forwarder, crt, network, editor, ui, draw, stub, startup, data-only, dead helpers or not code. The audit found no live rule of the game that is missing without being known: of the 17 not implemented rows, 12 have no known reference (finding GI-5), two are tails of registry rows (0x4674B8, 0x4EAEC2), and three are live and already in the documents (0x40D8A0, 0x4224E0 with PS15 and V4, 0x561520).
- **GI-4 No reconstruction slip and no new divergence in the 14 implemented rows.** Every difference the readers noted is already documented: the editor minus-button dispatch 0x55F5F0 (floor and equality rules CP4, CP6 and the degree sell without floor TC10, owner-decided; for a refused stat decrease the original picks the message from checks on base minus 2, an original slip ours replaces with the effective value), the hour lighting chain 0x57D6C0 (the original's own 3,600,000 ms chain, off during rest and travel; ours re-selects at every game hour and keeps updating; left out, registry rows 0x57D310 and 0x57D620), the clock getters (base year from the clock profile), the sector light loader 0x4F7464 (the original inserts at the list head and keeps per-light difference records; ours has the relocation arithmetic only), the spell record load body 0x44FE47 (typed refusals where the original exits) and the paid repair service 0x4C8EEA (waits for the barter window). One implemented row is exact: 0x4CB3F0 equals `WorldTravelRules.NearestKnownArea`.
- **GI-5 Twelve rule-shaped functions have no known caller.** 0x4C3120 (garbling of typed party-order text: a speaker flag replaces every word by a filler text, otherwise an effective intelligence below 5 replaces words of intelligence plus two letters or more; part of the known missing typed-order input of [H2-7](census-triage-h2.md#what-the-reading-found-that-the-earlier-documents-did-not-say)), 0x4C6BF0 and 0x4C6C50 (snapshot and restore of the 12 basic and 4 tech training tiers; the restore raises the key stat, adds skill points and re-applies the tiers; purpose unknown, nothing of ours does it), 0x4EBB50, 0x4EC460, 0x4EC870 (tile name flag test, facade name to art id, portal art id to prototype id), 0x4F0840 (re-runs the wall handler of every wall on a portal's tile), 0x4F1E70 (find the tile bucket that holds an object handle), 0x4F1F40 (restamp the locations of a whole sector list), 0x4F6E00 (check a facade walk-mask file header), 0x54ACB0 (the F10 compact interface toggle, a registered gap) and 0x57A1C0 (skill-bar target picked, start the skill; H2-8). Whether they are live through a call the export cannot see decides whether each is a task (T5).
- **GI-6 Original slips, all in functions with no known caller.** 0x458EC0 reads the out pointer before its null check, so the null branch is unreachable; 0x458F40 stores through the out pointer on its failure path whatever the pointer; 0x4DD520, 0x4DD600 and 0x4DD940 (siblings of the live light setters 0x4DD230, 0x4DD150 and 0x4DDB80) fall back to an unrelated argument as the overlay slot index when no slot bit is set, the quirk LT8 of the [world ledger](world.md) already notes for 0x4DD230; 0x4E1970 (editor wall rotate) never stops after the first valid rotation; 0x4DDC80 compares tints of different encodings; 0x45AB00 and 0x45AB20 have their names swapped (month and day, already in the ledger). If T5 shows that none is reached, the Original and Steamwoven settings are not touched.
- **GI-7 Two documentation corrections.** The doc comment of `Simulation.Hotkeys.HotkeyRules.ItemLocationBase` cites 0x4657A0 as the reader of the hotkey item location, but that function has no direct caller or pointer holder in the export and the constant is unused in ours (T3). The registry row of 0x503340 says its second entry 0x5033E0 sums frame offsets; the function counts art frames until the summed offsets reach limits, capped at 100, and returns the count; it too is editor-only (T3).
- **GI-8 Archive entry flag 0x800.** `DatArchive.ReadEntry` reads only plain 0x1 and zlib 0x2 entries and throws on any other flag value (a directory record 0x400 included), while the original lookup (0x53C1D0 and its caller 0x53C260) treats an entry with flag 0x800 as absent. **Settled by T4 (ARC-RES-124):** a scan of the eight R1 archives (the seven DAT files and `Arcanum.PATCH0`; 5,856 + 12,365 + 1,097 + 134 + 28 + 75,591 + 12,812 + 6 entries) found no entry with flag 0x800 and no flag bit outside plain, zlib and directory (`tools/research/dat_probe.py`); the exe read (0x53C1D0 returns absent for a set 0x800 bit) is confirmed, the case does not occur in the player's data, and `DatArchive` is left unchanged (see [DAT format](../../formats/dat.md#variants-flags-and-unknowns)).
- **GI-9 Small facts.** The menu start-type flag 0x5C4000 has only one writer in the export (0x541170), which has no direct caller or pointer holder; if nothing sets it, a start type of 0 always becomes 1; the default player creation 0x40D8A0 (from prototype 15 at the current map entry's start location) exists in the original and ours builds no default hero, a difference [PS6](../../architecture/original-persistence.md) and the content-product document already record; the animation run table's module load wrapper 0x4224E0 is live but our save writes no goal runs (PS15, V4, documented); the world map window destroy 0x561520 does not restart the ambient light chain in ours (documented, H2-2 and H2-11).
