## Function triage of the exe bands 0x50 to 0x54 (ARC-RES-119)

Source: slice H1 (V1, wave 2) of the [function audit plan](../function-audit-plan.md#5-recommendation) over the [census](../../verification/census.csv) of ARC-RES-106. Read on 2026-11-11 on the owner's Mac (`Arcanum.exe` 1.0.7.4, SHA-256 `9bd80511f8663a41a25a20a701959e394e0065e4ffc68a8dc69fe19c23678d52`, checked before the reading) with `llvm-objdump` (no Ghidra): fourteen readers took slices of the band's disassembly, each function with its callers, callees, strings, imports and the places of our code and documents that cite it, and the first reader's classification was checked against the executable and the code by the task (below). No second reading was made, so every row of this section is **F1**. The band holds 983 census function starts; 50 already had a row in [`functions.csv`](../../verification/functions.csv) and are unchanged; each of the other **933** is now a row there (the census is not regenerated).

The states of the audit plan map onto the registry's statuses, as in the [slice D ledger](census-triage-d.md): **not relevant** is `out of scope` with the reason class in front of the reason; **read and implemented** is `full` or `partial` with the `[OriginalFunction]` mark; **read and not implemented** is `not implemented` (also when our host does the work with no method of its own); **not yet read** would be `not implemented` at F0 (none is left in this band).

The band has three parts. 0x500000-0x5390FF is the engine library of the original (the "TIG" layer: art ids and art files, windows, the DirectDraw and Direct3D display, the network layer, keyboard and timers, the file and archive layer, Miles sound, Bink video, fonts, buttons); almost all of it is `out of scope`. 0x53C220-0x53EFFF is the archive reader (a part of the data format) and its pack tool. 0x53F000-0x54FFFF is the game interface of the main menu, the logbook, the options and save windows, character creation and the game's own bars; nearly all of it is `not implemented` because the viewer (`tools/terrain-viewer`, outside the assemblies the registry test loads) carries those behaviours, and the rows name the nearest class.

### Rules of this triage

- **Marks are strict.** A function is `partial` or `full` only when a method of ours in a loaded assembly carries its address in its own documentation, or is unambiguously the same rule (the art-id readers), and does what that function does for part of its callers. The first pass proposed 20 such rows, and the review added two more; 5 of the 20 were turned into `not implemented` rows that name the nearest code: three art-id helpers that our tile sound table reads inline (0x5036B0, 0x503900, 0x503950: no method has their result as its own), the opening shop refresh 0x545E80 (a class named by a reader that does not exist; the behaviour is spread over `AreaShopMerchant` and the session) and the interface window build 0x54A330 (only the mode stack reset at its end exists, which is the row 0x54AA30). One row was relaxed from `full` to `partial` (0x5045A0 answers the bit value, ours a bool). After the review two readers' `accessor` rows were marked `partial` for consistency with the neighbouring art-id readers (0x504C00 and 0x504C60: `EyeCandyArt.Translucent` and `Scale` read the same bits without the class test), and two rows moved: 0x52F0A0 (the mounted archive identity, read by the single-player module load) from `multiplayer` to `not implemented`, and 0x533020 (the sound fade start) from `audio engine` to `not implemented`; the options window close 0x541D70 joined the save window close 0x543580 as `other`.
- **`partial` says what is left out.** Each marked row states the missing part; the rest is the reading.
- **The viewer is not an assembly.** Rows whose behaviour only the viewer carries (menu, save window, character creation, HUD, logbook, button library, font and text layout) are `not implemented`; the reason names the viewer class so that the V4 gate can map them.
- **One census start can hold several functions.** Where a start covers a second function (for example 0x501DD0, 0x52E000, 0x5443E0) the row describes the start function and says what else sits in the range; the neighbour has no row of its own.
- **A callback slot is not the callback**, as in slice D; the data table at 0x53AC30 is not code (an `other` row).
