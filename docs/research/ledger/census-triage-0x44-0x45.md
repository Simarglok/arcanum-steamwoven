# Executable triage 0x44-0x45 (ARC-RES-108, V1 wave 1, slice C)

Status: **Research, docs and marks only** (2026-11-11). Slice C of [V1](../function-audit-plan.md#5-recommendation) of the function audit: every function start of the retail 1.0.7.4 `Arcanum.exe` in the address band 0x440000-0x45FFFF (scripts, goals, locks, magic) that the registry [`functions.csv`](../../verification/functions.csv) did not yet hold, with one state each. Addresses and prose only: no bytes, listings or oracle outputs.

## Scope and method

- The census ([`census.csv`](../../verification/census.csv), ARC-RES-106) has **523** function starts in the band; **132** already had a registry row and are unchanged (the RES-103 magic rows are taken as given). The other **391** were this slice (0x452830 and 0x45A060 got their own rows from other PRs while it was open, so **389** are added here): 311 of them are cited in a document, and all address-taken rows of the band are among them.
- Each function was read in the executable with `llvm-objdump` (no Ghidra), with its callers and the tables that hold its address, then compared with the code. Seven readers took address slices; the first-reader notes carry level F1, and a row that rests on an existing two-reader document row ([time loop](../../architecture/original-time-loop.md), [game event queue](../game-event-queue.md), spell-run ledger) carries F2 with that document as evidence. Names are Steamwoven's own.
- **Not read in full:** the network-packet branches of the functions (multiplayer is out of scope), the script-editor block at 0x44BD60 and, inside a few functions, callees outside the band (named in the row).
- The census starts are a scan: a few unreferenced neighbours sit inside a listed start and have no row of their own (0x440760, 0x441570, 0x442080, 0x443CA0, 0x443D50, 0x45C290, 0x45C9C0, 0x45CDB0, 0x45D070 and others); the rows describe them where they matter. Dead ones are noted under `dead`.

## Findings worth a task

These are the readings with the largest gap to our code; none is fixed here (V1 changes no behaviour). Each is a row below.

- **Spell runs across maps.** At a hero teleport the original moves the runs whose participants all travel into the destination map's carry file and force-ends every other run (0x44F7A0); at map close the remaining active runs are parked (0x44FA70) and at map entry restored with their ticks re-queued (0x44FC30). Ours keeps one run table across maps and carries or ends nothing at a teleport.
- **Spell component executors.** Of the 25 component types in the table at 0x5B0BA8 ours executes part of AGoal (goals 43 and 44), AGoalTerminate (hover), EyeCandy (a log entry), ObjFlag (4 flags) and Interrupt (a no-op in the original too). Not built: the creature half of Summon (the scenery half landed in ARC-DEV-352 at 0x452830 while this slice was open; list pick 0x452900, effect 0x450C40), Cast, ChargeNBranch, Dispel (0x451C40), AIRedirect, Terminate, TestNBranch, Trait, TraitIdx, Trait64, Recharge (0x454920) and Use (0x452ED0, which runs the target's use script). `SpellComponentOutcome.JumpTo` exists but nothing sets it.
- **Object creation tail.** The shared finish of every object created in play (0x442130, 0x4421A0, 0x442260: dynamic flag on the object and its inventory, listing in the loaded sector, light update, delayed NPC tick, restock, location notification) has no counterpart; each of our creation paths (projectile, missile, junk pile, made item) does its own.
- **Spatial lists and script entry.** The generic "objects at a tile", "objects in a rectangle" and "window vicinity" lists (0x4407C0, 0x440B40, 0x440FF0) exist only inside the spell host and the use-script host; the object script entry 0x441980 has no single dispatcher (script points 2, 3, 6, 7 and 8 have no host).
- **Scripts.** Script eye candy is only recorded, not played (0x44C7A0, 0x44C800); script action 130 (stop spell on object, 0x4593F0 and 0x459290) and the time-of-day actions (0x45A9E0 and its users) are missing; the peace helpers that end attack runs (0x44E050, 0x44E0E0) are not applied.
- **Walking and fire.** The path search adds 80 to a tile with a burning scenery object when the mover carries walk flag 0x400 (0x444500); our path requests have no such flag. Alt-click moves a loose object or critter onto the hero's tile (0x4445A0) and is not built.
- **Critters.** Missing: the combat-focus wipe (0x45ED70, 0x45ECE0), cancel of the pending body-decay event (0x45EC80), beds (0x45F2D0, 0x45F3A0), disband when a follower is destroyed (0x45E180), the summoned-associate test (0x45F460), the window-jump capability by art class (0x45F570), hide and show of hero and followers at travel (0x45E1E0).
- **Time.** Same-ping forced add (0x45B820) and the map-close removal of event kinds 1, 5, 10, 11, 12, 14 and 32 (0x45BCE0) are done differently (scope rules); the pause counter, parked per-map event files and the single millisecond clock are deliberate departures (owner decisions OQ1-OQ3, GI3, GI5) and are recorded in the rows, not as rechecks.
- **Party.** Leader and follower code knows only the hero as a leader (no chains through an NPC leader); join does not copy the leader's Tempus Fugit flag and removal does not clear the join-copied flags (0x45DE90, 0x45DFC0, 0x45E040).

Differences between our code and the executable that need the owner's eye are in [the owner re-check list](../../project/owner-recheck-list.md) under ARC-RES-108.
