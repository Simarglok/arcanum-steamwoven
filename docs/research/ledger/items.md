Anomalies:

- AMA1 (AM1, AM4): the merge sum, a destination's add and the weight product wrap past 32 bits. Crash class: both settings refuse a
  merge, an assembly or a received stack whose sum does not fit (`BudgetExceeded`).
- AMA2 (AM3, AM4): a negative count is accepted (a use with one grows the source). Both settings refuse a negative spend
  (`InvalidAmmo`) and a seed item with a negative count.
- AMA3 (AM3): a type outside 0..3 indexes past the tables. Crash class: both settings refuse such a seed item (the seed is refused)
  and a spend of such a type.
- AMA4 (AM5): a removal clears the critter's field while another stack of the type stays, so that stack is not counted until a
  later new stack sets the field again. Latent: each installed ammunition type has one prototype, so a holder never has two
  stacks of a type. The session spends from the holder's first stack of the type in both settings. **Decided** (owner, 2026-10-21):
  no switch, as for TC4 and TC6 (latent, unreachable in the installed data).
- AMA5 (AM6): a container's ammunition (and gold) is never found by the type lookups, so a device in a container has no cells.
  **Decided** (owner, 2026-10-21): a switch, `ItemRuleProfile.ContainerStackLookupFails` (ARC-TECHNOLOGY-009): Steamwoven finds the
  container's first stack of the type (a device in a container pays from its cells through `ContainerCellSource`, a spend from a
  container through `SpendAmmo`); Original keeps the failed lookup. Gold is not modelled; the same fix will apply to it.
- AMA6 (AM4, NT1): a source without a stack (or, for gold, a pile) still credits the destination. Since ARC-WORLD-071 the session
  moves units and coins between the hero and an NPC from a named ammunition stack or the NPC's first gold pile, and a source without one
  is refused in both settings (`ItemNotAvailable` for ammunition, `GoldShort` for gold): nothing is credited from nothing. Unreachable
  from the planned callers (a steal moves from the dragged pile or stack, PP3; a sale's price is capped at the merchant's gold, NT4).
  **Proposed** (ARC-WORLD-071): no switch while no caller reaches it; to be decided by the owner if one does.
  Since ARC-DEV-179 the dialog's `$$ n` (n > 0) reaches the null source of 0x464830 on purpose (a dialog reward comes from no object, GM2 in
  [scripts](scripts.md#dialog-money-code-arc-dev-179)): `GiveGoldToHero` credits the hero from nothing. A source object without a pile is still
  not reached by any caller, so its switch stays undecided.

ARC-WORLD-2216 read (F1, exports read, #2216): 0x580490 is the reset of the scroll-bar instance table of the generic widget 0x5804E0 (eight slots of 0x80 bytes at 0x684268, ledger [ALP10](character.md)): it empties each slot (0x5811C0), draws the first serial `random(0, 0x2000)` into 0x684678, and clears two UI globals. 0x581280 hands the next free slot a handle (slot index, serial) and counts the serial up; 0x5812E0 finds a slot back from a handle by comparing the slot index and the serial. The serial has no other reader or writer in the exe (two functions touch 0x684678), is never saved (the scroll-bar table is no game module) and is never shown: it only tells a stale handle from a live one, and a start value anywhere in 0..0x2000 behaves the same. The draw is made by the interface library init (0x53E600, via 0x580410) and by its reset (0x53E6E0, at every game reset: new game, load, death and game end; the 1807 "a load draws nothing" is about the skill roll alone). **Difference kept (decision of this task, #2216):** Steamwoven does not draw it. Its generator is SplitMix64 seeded from the clock, not the original's LCG, so no draw count or value is comparable with the original, and the draw would only shift every pinned sequence of tests and smokes for a value that decides nothing. A session's draws therefore stay one behind the original's after the gambling roll, as the 1807 note says.

**Differences kept.** A session the player starts throws the roll as its first draw (every later draw of such a session is one further along, as in the original); tests, smokes and a session restored from a save of schema 100 or lower, which holds no roll, throw it at the first barter window, so no other draw count moves; a move that
the session refuses (no room, a script, too few coins for a lost stack) puts the roll, the generator and the fate back (the original moves
the item first and never has to). The gate compares the unit price of 0x461F80 with the limit and the coins, as read, while a loss charges the whole stack (price × count, as every buy of the window); a stack the hero cannot pay for passes the gate and is refused with the window's "not enough money". A "won't sell" ware quotes 0 below Master haggle, so a hero with Master Gambling stakes it for 0 and a loss costs 0 (the gate and the flags 0x11 path read as one function, not observed at run time). A loss whose payment the session refuses (the new coin pile refused, the made number exhausted) moves nothing and puts the roll, the generator and the fate back. A lost bet with a price of 0 pays nothing and still counts as one change (the roll, the draws and the fate). The session refuses a stake the merchant's list does not show before the roll (a loss no longer moves the item, so nothing else would notice). Leftovers are GitHub issues.
