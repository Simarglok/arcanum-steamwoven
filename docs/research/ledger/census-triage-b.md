## Function triage of 0x420000-0x43FFFF (ARC-RES-118)

Task ARC-RES-118, V1 wave 2, slice B of the [function audit plan](../function-audit-plan.md#5-recommendation); it follows the wave 1 slices [C](census-triage-0x44-0x45.md), [D](census-triage-d.md), [E](function-audit-4b-4c.md) and [F](census-triage-4d-4f.md). The band holds the goal and action layer of the retail 1.0.7.4 `Arcanum.exe` (SHA-256 `9bd80511…3678d52`, checked before the reading): goal start, step and end nodes, the path-step and line-of-fire helpers, the projectile, missile, door, critter and eye candy goals, the roof and wall-check module, the settings list and the object helper layer. The [census](../../verification/census.csv) lists 458 function starts in it; 94 already had a row of [`functions.csv`](../../verification/functions.csv) and are unchanged. The other **364** each have one state below. The census is not regenerated.

## Scope and method

- **Read on 2026-11-11 on the owner's Mac** with `llvm-objdump` (no Ghidra, nothing of the listing stored). Five first readers each took one address share of the band (63 to 90 functions, balanced by size) and read every function above the accessor and forwarder level in the disassembly with its callers, callees, strings and data globals, then compared it with the code. I then checked every one of the {by["implemented"]} marks against the source (the method exists once and its own documentation comment carries the address), re-read 0x429BC0 and corrected its scope to partial, and looked at the differences found by the readers in the code (the independent review corrected five rows). Names are Steamwoven's own plain words.
- **One reader per function, so F1.** F2 only where an existing document row names the very address as the function it is about and states a second reading: 0x42FA50 and 0x42FD70 (goal table GT61 and GT65), 0x42FFE0 (ledger DA6 and goal table GT33), 0x43D940 and 0x43D990 (object model RL1).
- **Marks are strict (as in [slice D](census-triage-d.md#rules-of-this-triage)).** A function is `full` or `partial` with an `[OriginalFunction]` mark only when a method's own documentation comment carries its address and the method does that function's work for at least one of its callers. When the address appears only in a plain `//` comment, in the comment of an interface member, in a class comment or in a constructor, the function is `not implemented` and the row names the nearest method. A method that serves several addresses carries one mark for each.
- **A goal node is not a goal.** The original's goal table (see [goal table](../../architecture/goal-table.md)) is a list of small start, test, step and end functions; ours runs the goals as methods of the executor and the hosts. Where our executor does the work of a node with no method of its own, the row says `not implemented` and names the executor method; the V4 gate of the plan checks the unclaimed ones.
- **Goal numbers of unmarked nodes** that readers gave by slot arithmetic of the goal descriptor table (not by a document) are inferences; the rows say "goal N" only where a document or the table slot agrees.
- **Not done:** no Ghidra run, no oracle run, no smoke run, no second reading, no read of the network branches (multiplayer is out of scope) and no byte-by-byte read of the three biggest draw and path functions named under [not checked](#not-checked).

## Findings worth a task

Nothing is fixed here (V1 changes no behaviour). These are the readings with the largest gap to our code; each is a row below.

- **Wanderers never wander.** The original starts goal 65 (wander) and goal 66 (wander in the dark) for NPCs with the wander flags standing at their standpoint (0x435E60, 0x436040, destination planners 0x425930 and 0x425D60). Ours marks that step `AtStandpoint` as not implemented, so such an NPC stands still.
- **Please move and step apart.** Goal 68 (a critter asked to step aside, 0x4363E0, 0x424E00, the tile-sharer finder 0x436720) has only a descriptor; the executor calls `StepApart`, which the AI host leaves empty (0x4364D0), so critters stacked on one cell never separate. Built by ARC-AI-1315 for the attack starter's calls ([TS1–TS9](npc-ai.md#tile-sharers-please-move-and-step-apart-built-arc-ai-1315)).
- **Hit effects.** The blood eye candy of a hit (0x433020) and the weapon's own hit effect with its veto of the damage effect (0x4377C0) have no counterpart; the blood pool of a kill is covered.
- **Goals nobody starts.** Use item on a tile (goal 41: 0x4355F0, 0x429040, 0x429160), the pick pocket goal 17 write node (0x42BE80) and the window jump goal with its animation (0x42C780, 0x42D7D0, 0x42D910, 0x42F000, 0x42F140) are not runs of ours; a window step is an ordinary walk step and the vault is drawn by the body-move code.
- **NPC fidgets and skills.** The random idle fidget event with its candidate test (0x4300D0, 0x4302D0, 0x4303D0), the fidget and auto animation starters (0x435CE0, 0x42CDF0, 0x42CF40) and the NPC lock picking attempt (0x42A4E0, stubbed as not ready in the AI host) have no counterpart.
- **Path request modes.** The straight-line mode (flag 0x80, 0x420660) and the best-first search for the player (flag 0x1000, 0x420E30, dead in the shipped game) are not taken by our path request; the walker flags 0x200 and 0x400 are partly modelled by the path map (row 0x425BF0).
- **Object helper layer.** The object leaves-sector list (0x43CF70), the full teardown and free (0x43CFF0), the shared flag setter (0x43D0E0), art set (0x43EB30), light, overlay and light-slot setters (0x43EBD0, 0x43ECF0, 0x43EE10) and the overlay frame steppers have no single counterpart: our session writes state per feature and residency moves whole sets, by decision ([persistence](../../architecture/original-persistence.md), [object model](../../architecture/original-object-model.md)).
- **Walk step engine.** The step start, gait choice, pause time, offset border test and the step cost of 0x430FC0 are done by the host's gait timing and the turn-based cost rules, not by one method each (0x42E9B0, 0x42EDC0, 0x42EE90, 0x42EF60, 0x430FC0).

Differences between our code and the executable that need the owner's eye are in [the owner re-check list](../../project/owner-recheck-list.md) under ARC-RES-118.

## Not checked

- **Reading depth.** The first readers followed the full listing only of functions above the accessor and forwarder level and said where they did not: 0x420E30 (3,216 bytes) is dead by the ledger LR8 and its structure, not by a full read; 0x43AEC0 and 0x43B390 (object view draw) are drawing by structure; 0x42D440 and the stack slots of the pick locks loop were partly traced.
- **Goal numbers.** Goals 65, 66 and 68 and the node numbers of 0x425930, 0x425D60, 0x424E00 and 0x432D50 come from the descriptor table slots; the behaviour of the nodes was read directly.
- **Class calls that could be argued the other way:** 0x4246D0 (a forwarder that carries a no-round rule in its callers), 0x426F10 (a forwarder to 0x45D730, while `DyingAnimationRules.LiesFallen` carries the address), 0x43FDC0 (a forwarder to 0x43FE00; `LineOfFireRules.StepCost` names it), 0x42C610 (an accessor that copies one path byte into one frame slot), 0x437C50 (debug: its only caller uses the result for a log line).
- **Host methods marked.** `GameSessionOwner.CountStunnedTurn` (0x427000) and `AreaAiHost.BeginCast`, `AttemptSkill`, `ThrowItem`, `BeginAction` and `FaceForAction` sit in host classes; each is a method of its own whose documentation names the address, so each is marked, as in slice C. Whether the stun countdown belongs to the round loop is for the V2 ranking.
- **No second reading** was made, so no row of this slice is better than F1 unless named above.
