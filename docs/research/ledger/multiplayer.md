## Multiplayer (ARC-RES-072)

Source: [multiplayer research](../multiplayer-evidence.md). Read on 2026-10-27 on the owner's Mac (`Arcanum.exe`
1.0.7.4, SHA-256 `9bd80511f8663a41a25a20a701959e394e0065e4ffc68a8dc69fe19c23678d52`, checked before and during
the reading) by a first reader and, independently, a second reader that did not see the first verdicts (method
step 6). They agree on every row; the second reader's refinements (bit 0x4 means "game running", bit 0x40, the
split host and client branches of types 46, 59, 66, 80, 123, 128, NT9, NT12 and the contents of the character
file and the network save) were checked by the first reader and are included. Every direct branch stays inside
`.text`; none reaches `.IIDKing`. The questions are new: no earlier reading of the multiplayer range itself exists (rows of other sections already record the network branches of single functions, for example CL3), so a row
that states the read behaviour is "Original" and a row that looks unintended is "Original bug". Steamwoven is
single player: no row changes a rule setting now.
