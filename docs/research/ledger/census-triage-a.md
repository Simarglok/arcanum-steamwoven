## Executable triage of 0x40-0x41 (ARC-RES-117)

Task ARC-RES-117, V1 wave 2, slice A of the [function audit plan](../function-audit-plan.md#5-recommendation) (the band 0x400000-0x41FFFF; the next band is slice B). The band holds start-up, the save list, the object store and prototype files, the player module, the map list and map open, scrolling, the dialog and reaction code, sound schemes, the missing-art masks and the path request of the retail 1.0.7.4 `Arcanum.exe` (SHA-256 `9bd80511f8663a41a25a20a701959e394e0065e4ffc68a8dc69fe19c23678d52`, checked before the reading). The [census](../../verification/census.csv) lists 457 function starts in it: 55 had a row in [`functions.csv`](../../verification/functions.csv) already and are unchanged; the other **402** are this slice, and every one now has exactly one state below. The registry grew by **105 rows** (37 marked and 68 read and not implemented), and 297 functions are not relevant and recorded here only.

Read on 2026-11-11 on the owner's Mac with `llvm-objdump` (no Ghidra), by ten readers on address slices of about 10 KB of code each, who saw the repository's earlier readings and the code; the first reader of each slice is the only reader of its rows, so every row is **F1**, except the rows that point to an earlier two-reader ledger row (**F2**, with that row as evidence). Marks were then checked against the source by the author of this slice: a function is marked only when a method of an assembly the registry test loads does what that function does for some of its callers; properties, constants, host entries and viewer methods are `not implemented` rows that name the nearest method (two first-pass marks, 0x4197D0 and 0x41D390, were turned into such rows). Names are Steamwoven's own. No bytes, listings or oracle outputs are stored.

## Findings worth a task

None is fixed here (V1 changes no behaviour). Each is a registry row.

- **Run-time objects.** Creating an object from a prototype, freeing one and duplicating one (0x405800, 0x4058E0, 0x405BF0, 0x406210, and the temporary auto-level copy 0x405D60) have no counterpart; our records are immutable rows and the viewer's creation paths (junk pile, projectile, made item) each do their own. This is the first slice (Summon / run-time objects) of the [missing systems plan](../../project/missing-systems-plan.md).
- **Handle and ID conversion.** The original turns object handles into IDs at save, move and arrival and back at load, with a stale handle taking the last registry ID and a destroyed target becoming null (0x40BBF0, 0x40BD20, 0x40BDB0, 0x40BE70, 0x40BF00). Ours links by identity and has no handle layer, so the rule has no home; the architecture audit ([OM](../../architecture/original-object-model.md)) already covers it.
- **Dialog services.** The reply markers for the trainer, the healer, rumors, town directions, story and newspaper replies and the money request and payment steps (0x418A40..0x418C40, 0x418CA0..0x41A8C0) are not built; our dialog blocks them as unsupported interactions. The talk start's can-speak refusal and the kill-on-sight race line (0x412FD0) are missing too.
- **Paths.** The away path for back-off and escape (0x41F6C0) has our offset table but the world host answers no tile, so a back-off ends at once; the request flags 0x8, 0x40 and the fire check, the traversal mode (0x41F570) and the NPC search budget (0x41F9F0) are not built.
- **Barter and item-window phrases.** Sixteen phrase generators of the barter, gamble and item windows (0x413490..0x413910, 0x4139A0, 0x414020, 0x414540..0x414780) each run the can-speak test and pick an NPC or PC line range for the window; they are filed as `ui` (not relevant) because the lines belong to the windows, but the generated phrases are not built (see [original windows](../../ui/original-windows.md)).
- **Map open.** The map open and the in-game map open (0x40F4E0, 0x40FC70) and the player creation (0x40DB70) are spread over the session and viewer hosts, with no method of their own.

Differences between our code and the executable that need the owner's eye are in [the owner re-check list](../../project/owner-recheck-list.md) under ARC-RES-117.
